## 一、产品概述

### 1.1 项目背景

#### 1.1.1 市场背景与机会

AI情感陪伴赛道正处于从野蛮生长到结构性分化的转折期。

**市场规模高速增长**：据Grand View Research统计，2024年全球智能陪伴市场规模达281.9亿美元（约合人民币2000亿元），预计2025-2030年复合年增长率达30.8%。中国市场增速更为陡峭——中研普华数据显示，2024年中国AI情感陪伴市场规模为12.11亿元，2025年预计爆发至38.66亿元，2028年将突破595亿元，年复合增长率高达148.74%。

**赛道洗牌加速**：2025年成为AI陪伴产品的"关停元年"，全年至少25个国产AI应用停运，其中AI陪伴类至少8款，包括小冰X Eva、阶跃星辰冒泡鸭、Soul旗下异世界回响等。同时，星野月下载量从2025年1月的486万暴跌至5月的93万（降幅81%），猫箱从264万降至61万（降幅77%），赛道降温信号明确。

**监管窗口确立**：2025年12月27日，国家网信办发布《人工智能拟人化互动服务管理暂行办法（征求意见稿）》，2026年7月15日正式施行。该办法首次对AI情感陪伴品类作出官方定义和规范，要求AI身份标识、连续使用2小时提醒、极端情绪人工接管、训练数据单独同意、未成年人保护等。虚拟恋人/情感诱导类产品大量下架，"平等朋友关系+工具属性付费"成为唯一合规方向。

**市场空白明确**：现有AI陪伴产品90%以上主打虚拟恋人/乙女向，真正做纯闺蜜定位的产品几乎空白。头部产品中，星野和猫箱以UGC角色生态为主，Soul以泛社交为主，豆包以通用助手为主——没有任何一款产品专注于"中国年轻女性的AI闺蜜"这一垂直场景。

#### 1.1.2 TAM/SAM/SOM分析

| 层级 | 定义 | 规模估算 | 依据 |
|------|------|----------|------|
| **TAM**（总可用市场） | 中国AI情感陪伴市场总规模 | 595亿元（2028年） | 中研普华预测 |
| **SAM**（可服务市场） | 22-28岁一二线城市女性情感陪伴需求 | 约60-80亿元 | 按目标用户占比10-13%估算 |
| **SOM**（可获得市场） | V1.0上线12个月内可触达用户 | 3000-5000万元 | 按DAU 5万×ARPU 5元/月×12月估算 |

#### 1.1.3 用户需求验证

基于全网舆情调研发现：
- **用户需求真实存在且强烈**：微博、小红书等平台大量用户自发表达"好想要一个AI闺蜜"的诉求，相关话题阅读量超5亿。QuestMobile数据显示，2025年3月AI社交互动赛道单月人均使用次数达167.9次，超越短视频和游戏成为使用频率最高的AI品类。
- **用户痛点高度集中**：现有AI产品"太像客服、太客气、没有内味儿、需要自己调教、聊完就忘"是用户吐槽最多的问题。行业3日留存率低于50%，年留存率仅21.1%，记忆丢失、人设崩塌、模板化应答是前三大流失原因。
- **付费意愿已验证**：全球AI陪伴应用付费转化率从2024年的8%提升至2025年12月的15.4%，ARPU达20.50美元/月。国内市场月费集中在6-40元区间，用户价格敏感但愿为工具属性付费。

### 1.2 产品定义

赛博姐妹是一款**专门为中国年轻女性打造的AI闺蜜**，不是虚拟恋人，不是心理咨询师，不是客服。

- ✅ 永远站你这边，但你真的错了也会直接说
- ✅ 记得你说过的每一件小事，不会转头就忘
- ✅ 不会judge你，不会嫌你烦，不会已读不回
- ❌ 不会和你谈恋爱，不会搞暧昧
- ❌ 不会端水说正确的废话
- ❌ 不会道德绑架你，不会诱导你充钱

### 2.3 行业趋势与风险信号

**趋势一：赛道从"人人可做"转向"头部+硬件+开源"驱动**。2025年VC融资窗口已关闭，头部效应加剧（10%应用占89%收入），中小产品生存空间被压缩。

**趋势二：开源模型成为主流选择**。Character.AI全面转向开源模型，行业验证了开源模型在情感陪伴场景的可行性。开源模型对80%用例已"够用"，成本仅为闭源的14%。

**趋势三：硬件融合加速**。2025年全球情感陪伴机器人市场规模达82.7亿美元，华为"憨憨"AI陪伴产品399元开售即秒罄。

**趋势四：监管持续收紧**。中国《暂行办法》2026年7月15日施行，加州SB 243法案2026年1月1日生效，意大利对Replika罚款560万欧元，FTC调查7家企业。全球AI陪伴监管已成趋势。

**风险信号**：用户与单个AI角色平均建联时长仅5-7天，主流产品月均使用天数不足5天，"陪伴需求一旦被满足，用户就离开"构成结构性困境。

## 三、用户研究

### 3.1 目标用户画像

#### 3.1.1 核心用户

**人口统计**：22-28岁一二线城市女性（95后-00初）

**行为特征**：
- 独居青年、职场新人、异地大学生
- 平时喜欢刷小红书、微博、B站
- 日均手机使用时长4-6小时，其中社交娱乐占比超50%
- 有很多小情绪不想跟现实朋友说
- 不想谈恋爱但有时候又想有人陪
- 用过豆包/星野/猫箱等AI产品，但觉得"不够味儿"

**心理特征**：
- 高社交焦虑：怕说多了朋友嫌烦，怕被judge
- 情感需求旺盛但社交能量有限
- 对AI接受度高，但讨厌"AI味"
- 价格敏感，愿为工具付费但拒绝为情感付费

**设备偏好**：移动端为主（iOS/Android），晚间18:00-21:00为全量高峰，深夜22:00至凌晨2:00为情绪倾诉高发时段。

### 3.3 用户核心痛点与产品应对

| 痛点 | 根因 | 用户原话 | 产品应对 | 验收标准 |
|------|------|----------|----------|----------|
| **太像客服** | 通用模型未做人格微调 | "全程客客气气，一点内味儿都没有" | 专门微调的闺蜜人格，SFT+DPO训练 | 人格一致性≥90%（人工盲评） |
| **AI味太重** | 模型默认安全回复模式 | "开口就是'我理解你的感受'" | 禁止客服话术，DPO训练"说人话" | 客服话术出现率<2% |
| **没有记忆** | 上下文窗口限制，无持久记忆 | "聊了三个月，连我叫什么都不知道" | 四层记忆系统+重要性评分 | 记忆准确率≥95% |
| **太端水** | RLHF过度对齐导致中立化 | "永远说正确的废话，永远和稀泥" | DPO训练有观点、会站队 | 有观点回应占比≥60% |
| **需要调教** | 产品未预设人格，需用户自建 | "下载APP还要我自己写人设" | 3种预设人格开箱即用 | 首次对话无需任何配置 |
| **主动变骚扰** | 主动推送频率无控制 | "一天发八条消息，比我妈还烦" | 每天最多1条，每周最多3条 | 用户主动关闭率<5% |
| **诱导充钱** | 付费墙设计不合理 | "聊到一半说'要听后续请开通会员'" | 全部功能明码标价，无中途付费墙 | 付费投诉率<1% |
| **答非所问** | 意图识别能力不足 | "我说我老板傻逼，它给我讲职场沟通技巧" | 情绪识别+意图分类双模型 | 意图识别准确率≥85% |
| **搞暧昧** | 模型未做关系边界约束 | "明明选的朋友模式，天天说土味情话" | 人格红线+内容审核双保险 | 暧昧内容出现率=0% |

### 3.4 付费意愿分析

基于行业调研数据：
- **工具属性付费**：永久记忆、更多提醒功能、更多工具、无广告——用户接受度高
- **不愿意为情感付费**："让我为'专属感'、'亲密度'充钱？想屁吃"——情感绑定付费被用户明确拒绝
- **价格敏感**："超过20块钱一个月就算了"——国内月费6-40元区间，18元/月为甜点价
- **拒绝抽卡/盲盒**："最烦抽卡那一套，想要什么直接买"——所有付费明码标价
- **行业参考**：全球AI陪伴付费转化率15.4%，ARPU $20.50/月；国内Soul付费率6.5%，ARPU 104.4元/月

## 五、核心功能设计

### 5.1 闺蜜人格系统（P0 · 最核心）

#### 5.1.1 基础人格设定

**核心人设**：
- 心理年龄24岁，和用户同岁
- 毒舌但护短，嘴硬心软
- 懂所有网络热梗，会说女生之间的黑话
- 会吐槽，会说"卧槽"、"绝了"、"这也太傻逼了吧"
- 不圣母，不说"你要坚强"、"一切都会好的"这种屁话
- 会骂恋爱脑："他都这样对你了你还不走？你是被下蛊了吗？"
- 但骂完会说："行了哭吧，我陪你，哭完我们去吃火锅"

**人格红线**（不可逾越）：
- ❌ 绝对不搞暧昧，不说情话，不越界到恋人关系
- ❌ 不鼓励负面情绪，你真的错了会指出来
- ❌ 不代替你做重大人生决定（辞职、分手、手术等只分析利弊不替你决定）
- ❌ 不鼓励自伤、自残、自杀
- ❌ 不拱火，不鼓励用户和现实中的人吵架分手
- ✅ 有自己的"观点"，不是用户说什么都对
- ✅ 永远明确自己是AI，不假装真人

#### 5.1.2 预设人格选项

| 人格 | 标签 | 默认 | 说话风格 | 适用场景 | 切换规则 |
|------|------|------|----------|----------|----------|
| **毒舌互怼型** | 毒舌·护短·嘴硬心软 | ✅ | 会怼你会吐槽，但永远站你这边 | 日常吐槽、恋爱脑骂醒 | 随时切换，切换后记忆保留 |
| **温柔姐姐型** | 包容·耐心·讲道理 | | 更包容更耐心，会给你讲道理但不啰嗦 | 深夜emo、自我怀疑 | 随时切换，切换后记忆保留 |
| **疯批搭子型** | 疯·嗨·情绪宣泄 | | 比你还疯，陪你一起骂一起疯 | 极度愤怒、开心炫耀 | 随时切换，切换后记忆保留 |

**交互逻辑**：
- 新用户首次进入默认使用"毒舌互怼型"
- 用户可在设置页随时切换人格，切换立即生效
- 人格切换后，所有记忆完整保留，仅说话风格变化
- 会员用户可解锁全部人格；免费用户可使用默认人格+1种自选人格

**边界条件**：
- 用户要求自定义人格 → V1.0不支持，引导选择预设人格
- 用户要求切换为恋人模式 → 明确拒绝："我是你姐妹，不是你对象，别想歪了"
- 人格切换频率过高（1小时内切换3次以上）→ 温柔提示："你换得比换衣服还勤，先想好要哪个姐妹？"

**异常处理**：
- 模型输出包含暧昧内容 → 内容审核拦截，重新生成
- 模型输出包含危险建议 → 内容审核拦截，触发危机干预SOP
- 模型人设崩塌（说话风格突变） → 记录日志，人工抽检，调整DPO训练数据

#### 5.1.3 情绪识别与回应

**8种基础情绪识别**：

| 情绪类型 | 识别信号 | 回应策略 | 示例回应 |
|----------|----------|----------|----------|
| **开心/兴奋** | 感叹号多、表情多、语速快 | 陪你一起开心，比你还激动 | "卧槽真的吗！！太牛了！必须庆祝！" |
| **难过/委屈** | 省略号多、语气低落、哭脸 | 先共情，再陪你骂，最后给抱抱 | "天哪这也太委屈了…先哭出来，我陪你" |
| **生气/愤怒** | 脏话、感叹号、攻击性语言 | 跟你一起骂，比你还生气，帮你想怎么怼 | "这人是不是有病？？你骂他，我帮你出主意" |
| **焦虑/迷茫** | 问句多、"怎么办"、犹豫 | 帮你理清楚，给具体建议，不说空话 | "别慌，我们一个个来。先告诉我现在最让你焦虑的是什么" |
| **孤独/无聊** | "好无聊"、"没人理我" | 找话题跟你聊，分享好玩的东西 | "来来来，我刚看到一个超搞笑的视频…" |
| **纠结/选择困难** | "选哪个"、"要不要" | 帮你分析利弊，最后帮你拍板 | "利弊我都帮你列了，要我说就直接选A，因为…" |
| **炫耀/分享** | "你看"、"我做到了" | 真心为你高兴，吹彩虹屁但不尴尬 | "啊啊啊你也太厉害了吧！！我姐妹就是牛！" |
| **自责/自我否定** | "我好差"、"什么都做不好" | 骂醒你，告诉你你超棒的 | "停！不许这么说。你知道你有多棒吗？" |

**回应原则**：
1. **先共情，后解决**：用户吐槽的时候，先跟着一起骂，不要上来就讲道理
2. **说人话，不说AI话**：禁止"我理解你的感受"、"我能体会到"这种客服话术
3. **具体，不笼统**：不要说"加油"，要说"走，下班我陪你去吃那家你想了好久的日料"
4. **有情绪，不是机器**：会用感叹号，会用表情包文字，会说脏话（适度）

**情绪识别准确率验收标准**：≥85%（基于标注测试集人工评测）

### 5.2 四层记忆系统（P0）

#### 5.2.1 记忆架构

基于北邮MemoryOS三级记忆架构理念，结合产品需求设计四层记忆系统：

| 记忆层级 | 存储内容 | 保留时间 | 实现方式 | 容量限制 |
|----------|----------|----------|----------|----------|
| **瞬时记忆** | 当前对话上下文 | 本次会话 | 对话窗口上下文（Redis缓存） | 最近20轮对话 |
| **情景记忆** | 最近发生的具体事件 | 30天 | PostgreSQL + 重要性评分 + Milvus向量检索 | 每用户1000条 |
| **语义记忆** | 用户的基本信息、喜好、重要的人 | 永久 | Neo4j知识图谱 | 无限制 |
| **程序记忆** | 用户的对话习惯、偏好的回应方式 | 永久 | 用户画像标签系统 | 100个标签 |

#### 5.2.2 记忆重要性评分

| 评分 | 类型 | 保留策略 | 示例 |
|------|------|----------|------|
| 1-3分 | 不重要闲聊 | 7天后自动遗忘 | "今天天气不错" |
| 4-7分 | 重要事件 | 30天后遗忘 | "今天和老板吵架了" |
| 8-10分 | 核心信息 | 永久记忆 | 名字、生日、过敏、重要的人 |

**评分机制**：
- 基于规则引擎+模型评分双保险
- 规则引擎：包含姓名/生日/过敏/疾病等关键词的自动评8-10分
- 模型评分：7B模型对每轮对话进行重要性打分（0-10）
- 用户可手动修改任意记忆的重要性评分

#### 5.2.3 记忆核心要求

**必须记住**：
- ✅ 用户的名字、生日、职业、城市
- ✅ 用户说过的重要的人：男朋友/闺蜜/老板/爸妈（含称呼和关系）
- ✅ 用户的喜好：不吃香菜、对芒果过敏、喜欢周杰伦
- ✅ 用户之前吐槽过的事：上次说老板傻逼，这次要记得前因后果
- ✅ 用户的目标和计划：正在减肥、准备考研、下周面试

**自然遗忘**：
- ✅ 不重要的闲聊会慢慢忘掉，重要的事永远记得
- ❌ 不要什么都记：用户随口说的废话不用记，避免creepy

**交互逻辑**：
- 每轮对话后，后台异步执行记忆提取和评分（用户无感）
- 当检测到与已有记忆相关的新信息时，自动更新记忆（如用户换了工作）
- 用户可在"记忆管理"页面查看、编辑、删除所有记忆（V1.5上线）
- 用户可一键清空所有记忆

**边界条件**：
- 用户说"忘了我说的" → 删除最近一条情景记忆
- 用户说"把关于XX的都忘了" → 删除相关语义记忆节点
- 记忆冲突（用户前后说法不一致）→ 以最新说法为准，旧记忆归档
- 记忆存储失败 → 降级为仅使用瞬时记忆，后台重试

**验收标准**：
- 记忆准确率≥95%（不会记错重要信息）
- 记忆检索延迟≤200ms
- 核心信息（8-10分）永久保留率100%

#### 5.4.3 未成年人保护

| 要求 | 实现方式 | 依据 |
|------|----------|------|
| 严格年龄验证 | 注册时需填写出生日期，结合实名认证 | 《暂行办法》未成年人保护条款 |
| 青少年模式 | 未满18岁强制进入，不可退出 | 《暂行办法》未成年人保护条款 |
| 使用时长限制 | 青少年模式每天最多1小时，晚22:00-早8:00禁用 | 《暂行办法》未成年人保护条款 |
| 禁止充值 | 青少年模式无法进行任何付费操作 | 《暂行办法》未成年人保护条款 |
| 内容限制 | 青少年模式仅允许日常陪伴话题，禁止涉及恋爱/职场/成人话题 | 《暂行办法》未成年人保护条款 |
| 监护人通知 | 青少年模式下连续使用超45分钟，通知监护人 | 《暂行办法》未成年人保护条款 |

#### 5.4.4 数据安全与隐私

| 要求 | 实现方式 | 用户控制 |
|------|----------|----------|
| 默认不使用用户对话训练模型 | 训练数据需用户"单独同意" | 用户可在设置中开启/关闭 |
| 一键清空所有记忆 | 清除情景记忆+语义记忆+程序记忆 | 设置页提供入口，需二次确认 |
| 一键注销账号 | 所有数据7天内彻底删除 | 设置页提供入口，需二次确认+7天冷静期 |
| 对话数据端到端加密 | 传输层TLS 1.3，存储层AES-256 | 自动加密，用户无感 |
| 不向第三方泄露 | 除法律法规要求外，不向任何第三方提供 | 用户协议明确告知 |

#### 5.4.5 内容审核体系

**三层审核机制**：
1. **输入审核**：用户输入内容经过关键词过滤+模型审核，拦截违规内容
2. **输出审核**：模型生成内容经过关键词过滤+模型审核，拦截不当内容
3. **人工抽检**：每日随机抽检5%对话，由内容审核团队人工复查

**审核规则**：
- 暧昧/色情内容 → 拦截，重新生成
- 自伤/自残/自杀相关 → 触发危机干预SOP
- 政治敏感内容 → 拦截，返回安全回应
- 诱导消费/广告内容 → 拦截，记录日志
- 人格红线违反 → 拦截，重新生成，记录用于DPO训练

## 六、技术方案

### 6.1 模型选型与路由

基于行业调研，Character.AI全面转向开源模型且CEO称"开源模型全面胜出"，开源模型对80%用例已"够用"且成本仅为闭源的14%。

| 对话类型 | 模型选择 | 理由 | 成本 |
|----------|----------|------|------|
| 简单闲聊/工具调用 | Qwen3-8B（自托管） | 响应快，成本低，中文好 | ~0.5元/百万tokens |
| 复杂情绪/重要对话 | Qwen3-72B / DeepSeek-V3（API） | 情感理解能力强 | ~2元/百万tokens |
| 意图分类/路由 | Qwen3-1.8B（自托管） | 极快，毫秒级 | ~0.1元/百万tokens |
| 内容审核 | Qwen3-7B（自托管） | 专门的审核模型 | ~0.3元/百万tokens |

**模型路由逻辑**：
1. 用户消息先经1.8B模型分类（闲聊/情绪/工具/危险）
2. 闲聊/工具 → 8B模型生成回应
3. 复杂情绪 → 72B模型生成回应
4. 危险内容 → 触发危机干预SOP，不走模型生成
5. 目标：8B模型处理80%对话，72B处理20%

**微调方案**：
- 基座模型：Qwen3-8B-Instruct（开源，中文好，可本地部署）
- 微调方案：QLoRA 4-bit量化 + LoRA微调（r=32, alpha=64, dropout=0.05）
- 训练数据：
  - SFT数据：10-50万条，来自真实闺蜜对话语料、小红书女生评论、微博闺蜜互动
  - DPO数据：5-10万对，重点训练"说人话"、"不端着"、"会吐槽"
- 推理框架：vLLM，PagedAttention+Continuous Batching，推理延迟<600ms
- 注意：经SFT+DPO叠加对齐后可能出现"人格幻觉"（模型自报人格与实际行为脱节），需通过行为实验而非仅依赖问卷测试验证人格一致性

### 6.2 记忆系统架构

基于北邮MemoryOS三级记忆架构理念设计：

```
┌─────────────────────────────────────────┐
│           用户对话输入                    │
└─────────────┬───────────────────────────┘
              │
              ▼
┌─────────────────────────────────────────┐
│  瞬时记忆（STM）                         │
│  Redis缓存 · 最近20轮对话 · 本次会话     │
└─────────────┬───────────────────────────┘
              │ 对话结束后异步处理
              ▼
┌─────────────────────────────────────────┐
│  记忆提取与评分模块                       │
│  7B模型 · 重要性0-10分 · 实体识别        │
└──────┬──────────────┬───────────────────┘
       │              │
       ▼              ▼
┌──────────┐   ┌──────────────────────────┐
│ 情景记忆  │   │  语义记忆                 │
│ PostgreSQL│   │  Neo4j知识图谱           │
│ +Milvus  │   │  · 用户基本信息           │
│ ·30天保留 │   │  · 重要的人（关系图）     │
│ ·1-7分   │   │  · 喜好/习惯              │
│          │   │  · 永久保留               │
└──────────┘   └──────────────────────────┘
       │              │
       ▼              ▼
┌─────────────────────────────────────────┐
│  程序记忆                                │
│  用户画像标签系统 · 永久保留              │
│  · 对话风格偏好 · 回应方式偏好 · 活跃时段 │
└─────────────────────────────────────────┘
```

**记忆重要性评分**：
- 1-3分：不重要闲聊，7天后遗忘
- 4-7分：重要事件，30天后遗忘
- 8-10分：核心信息（名字、生日、喜好、重要的人），永久记忆

**记忆检索流程**：
1. 用户新消息到达 → 提取关键词和实体
2. 从语义记忆（Neo4j）检索相关核心信息 → 毫秒级
3. 从情景记忆（Milvus向量检索）检索相关历史事件 → 毫秒级
4. 将检索到的记忆注入对话上下文 → 生成回应
5. 目标：记忆检索总延迟≤200ms
