### 1.4 选型理由

**为什么React+TailwindCSS而非Vue?**
- 原型设计的Design Token（CSS变量体系）与TailwindCSS配置高度映射
- React生态中聊天UI组件库更成熟
- 状态管理复杂度（聊天+记忆+工具+用户）适合Zustand

**为什么Node.js而非Python FastAPI?**
- 前后端统一JavaScript/TypeScript，开发效率高
- Express生态成熟，中间件丰富
- 后续接入LLM API只需HTTP调用，语言无关

**为什么Prisma而非原生SQL?**
- 类型安全的数据库访问
- 自动迁移管理
- 开发体验好，减少SQL编写错误

**为什么微服务架构?**
- 支持水平扩展，应对DAU 5万目标
- 服务自治，独立部署，降低耦合度
- 故障隔离，单个服务故障不影响整体系统
- 技术栈灵活，不同服务可选择最适合的技术

### 2.2 微服务架构

### 2.3 数据架构

#### 2.3.1 数据库职责

| 数据库 | 数据类型 | 访问模式 | 一致性要求 |
|--------|----------|----------|------------|
| **PostgreSQL** | 用户数据、会话、消息、工具数据 | 读写混合 | 强一致性 |
| **Redis** | 会话缓存、热点数据、消息队列 | 高频读写 | 最终一致性 |
| **Neo4j** | 用户关系图、知识图谱 | 图查询 | 最终一致性 |
| **Milvus** | 向量数据、语义检索 | 向量相似度搜索 | 最终一致性 |

#### 2.3.2 数据流

```
用户输入 → API网关 → 对话服务 → LLM服务 → 对话服务 → 用户
                ↓
            记忆服务 → PostgreSQL + Neo4j + Milvus
                ↓
            消息队列 → 异步处理
```

## 3. 数据库Schema

### 3.1 用户表 (users)

```sql
CREATE TABLE users (
  id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  phone         VARCHAR(20) UNIQUE NOT NULL,
  nickname      VARCHAR(50),
  avatar_url    TEXT,
  persona       VARCHAR(20) DEFAULT 'toxic',  -- toxic/gentle/wild
  is_vip        BOOLEAN DEFAULT false,
  vip_expire_at TIMESTAMPTZ,
  birth_date    DATE,                          -- 未成年人检测
  created_at    TIMESTAMPTZ DEFAULT now(),
  updated_at    TIMESTAMPTZ DEFAULT now(),
  deleted_at    TIMESTAMPTZ                    -- 软删除
);

-- 索引
CREATE INDEX idx_users_phone ON users(phone) WHERE deleted_at IS NULL;
CREATE INDEX idx_users_created_at ON users(created_at);
CREATE INDEX idx_users_is_vip ON users(is_vip) WHERE is_vip = true;
```

### 3.2 会话表 (conversations)

```sql
CREATE TABLE conversations (
  id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id       UUID REFERENCES users(id) ON DELETE CASCADE,
  title         VARCHAR(100),
  persona       VARCHAR(20) DEFAULT 'toxic',
  created_at    TIMESTAMPTZ DEFAULT now(),
  updated_at    TIMESTAMPTZ DEFAULT now()
);

-- 索引
CREATE INDEX idx_conversations_user_id ON conversations(user_id);
CREATE INDEX idx_conversations_created_at ON conversations(created_at);
CREATE INDEX idx_conversations_user_created ON conversations(user_id, created_at DESC);
```

### 3.3 消息表 (messages)

```sql
CREATE TABLE messages (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  conversation_id UUID REFERENCES conversations(id) ON DELETE CASCADE,
  role            VARCHAR(10) NOT NULL,  -- 'user' | 'assistant'
  content         TEXT NOT NULL,
  emotion         VARCHAR(20),           -- 情绪标签
  importance      INTEGER DEFAULT 3,     -- 重要性评分 1-10
  created_at      TIMESTAMPTZ DEFAULT now()
);

-- 索引
CREATE INDEX idx_messages_conversation_id ON messages(conversation_id);
CREATE INDEX idx_messages_created_at ON messages(created_at);
CREATE INDEX idx_messages_conversation_created ON messages(conversation_id, created_at DESC);
CREATE INDEX idx_messages_role ON messages(role);
CREATE INDEX idx_messages_importance ON messages(importance) WHERE importance >= 7;

-- 分区表（按月分区）
CREATE TABLE messages (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  conversation_id UUID NOT NULL,
  role            VARCHAR(10) NOT NULL,
  content         TEXT NOT NULL,
  emotion         VARCHAR(20),
  importance      INTEGER DEFAULT 3,
  created_at      TIMESTAMPTZ DEFAULT now()
) PARTITION BY RANGE (created_at);
```

### 3.4 记忆表 (memories)

```sql
CREATE TABLE memories (
  id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id     UUID REFERENCES users(id) ON DELETE CASCADE,
  type        VARCHAR(20) NOT NULL,   -- 'episodic' | 'semantic' | 'procedural'
  content     TEXT NOT NULL,
  entities    JSONB,                   -- 提取的实体 {"name":"小明","relation":"男友"}
  importance  INTEGER DEFAULT 5,       -- 1-10
  tags        TEXT[],
  expires_at  TIMESTAMPTZ,            -- NULL=永久
  created_at  TIMESTAMPTZ DEFAULT now(),
  updated_at  TIMESTAMPTZ DEFAULT now()
);

-- 索引
CREATE INDEX idx_memories_user_id ON memories(user_id);
CREATE INDEX idx_memories_type ON memories(type);
CREATE INDEX idx_memories_importance ON memories(importance);
CREATE INDEX idx_memories_user_type ON memories(user_id, type);
CREATE INDEX idx_memories_user_importance ON memories(user_id, importance DESC);
CREATE INDEX idx_memories_expires_at ON memories(expires_at) WHERE expires_at IS NOT NULL;
CREATE INDEX idx_memories_entities ON memories USING GIN(entities);
```

## 5. 核心功能设计

### 5.1 记忆系统架构

基于北邮MemoryOS三级记忆架构理念设计：

```
┌─────────────────────────────────────────┐
│           用户对话输入                    │
└─────────────┬───────────────────────────┘
              │
              ▼
┌─────────────────────────────────────────┐
│  瞬时记忆（STM）                         │
│  Redis缓存 · 最近20轮对话 · 本次会话     │
└─────────────┬───────────────────────────┘
              │ 对话结束后异步处理
              ▼
┌─────────────────────────────────────────┐
│  记忆提取与评分模块                       │
│  7B模型 · 重要性0-10分 · 实体识别        │
└──────┬──────────────┬───────────────────┘
       │              │
       ▼              ▼
┌──────────┐   ┌──────────────────────────┐
│ 情景记忆  │   │  语义记忆                 │
│ PostgreSQL│   │  Neo4j知识图谱           │
│ +Milvus  │   │  · 用户基本信息           │
│ ·30天保留 │   │  · 重要的人（关系图）     │
│ ·1-7分   │   │  · 喜好/习惯              │
│          │   │  · 永久保留               │
└──────────┘   └──────────────────────────┘
       │              │
       ▼              ▼
┌─────────────────────────────────────────┐
│  程序记忆                                │
│  用户画像标签系统 · 永久保留              │
│  · 对话风格偏好 · 回应方式偏好 · 活跃时段 │
└─────────────────────────────────────────┘
```

### 5.2 记忆重要性评分

- 1-3分：不重要闲聊，7天后遗忘
- 4-7分：重要事件，30天后遗忘
- 8-10分：核心信息（名字、生日、喜好、重要的人），永久记忆

### 5.3 记忆检索流程

1. 用户新消息到达 → 提取关键词和实体
2. 从语义记忆（Neo4j）检索相关核心信息 → 毫秒级
3. 从情景记忆（Milvus向量检索）检索相关历史事件 → 毫秒级
4. 将检索到的记忆注入对话上下文 → 生成回应
5. 目标：记忆检索总延迟≤200ms

### 5.4 多智能体协作架构（V2.0远期）

参考Soul虚拟伴侣的多Agent实践，V2.0可引入多智能体协作：

| Agent | 职责 | 优先级 |
|-------|------|--------|
| **对话Agent** | 生成闺蜜风格回应 | V1.0 |
| **记忆Agent** | 记忆提取、评分、检索 | V1.0 |
| **情绪Agent** | 分析对话情感倾向 | V1.0 |
| **内容Agent** | 主动生成日常关怀内容 | V1.5 |
| **安全Agent** | 内容审核与危机干预 | V1.0 |

通过MCP协议接入外部工具生态（天气、日历、待办等），V2.0可进一步扩展Agent能力。

### 7.2 告警规则

```yaml
# alerts.yml
groups:
  - name: service_alerts
    rules:
      - alert: ServiceDown
        expr: up == 0
        for: 1m
        labels:
          severity: critical
        annotations:
          summary: "Service {{ $labels.job }} is down"
      
      - alert: HighErrorRate
        expr: rate(http_requests_total{status=~"5.."}[5m]) / rate(http_requests_total[5m]) > 0.05
        for: 2m
        labels:
          severity: warning
        annotations:
          summary: "High error rate on {{ $labels.job }}"
      
      - alert: CrisisEventDetected
        expr: increase(crisis_events_total[5m]) > 0
        for: 0m
        labels:
          severity: critical
        annotations:
          summary: "Crisis event detected"
```
