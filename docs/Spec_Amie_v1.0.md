## 1. 产品与架构边界

当前产品是模块化单体，不是微服务平台。单机 Docker Compose 运行 Nginx、主 Web、API、PostgreSQL 和一次性 migration job。Nginx 提供用户域名上的 TLS，同源暴露 `/api/`。

2026-09-07 云端切割（用户拍板）：目标用户是手机用户，跑不了本地模型，聊天从「llama.cpp 本地优先 + Qwen 备用」切换为**云端唯一路径**（供应商槽 `GATEWAY_QWEN_*`，供应商中立）；llama.cpp 管理面、虚拟试衣/化妆间（本机 ComfyUI）、服务器侧执行能力（bash_run、内置浏览器、工作模式生图、SKILL.md 技能、JS 插件、MCP）全部删除下线。

2026-09-15～16 功能收拢（产品负责人拍板，理由是「太花哨、太杂」，要求高内聚、低耦合）：一个 Amie 只有三种说话方式，取消角色扮演；只有一种对话，取消聊天/工作模式；日程、倒数日、提醒、手帐打卡、专注自习合成一个「安排」（番茄钟下线）；日记、读书、来信合成「手记」；化妆间与 3D 衣柜合成「装扮」；经期单独保留。

2026-09-19 重构（产品负责人拍板）：只有一个 Web 版，「安排 / 手记 / 经期 / 装扮」与对话、「她」、设置对所有人开放；本机能力（文件、代码、浏览器、生图、后台任务）保留，只在 API 跑在用户自己电脑上时开放，托管 Web 连接用户电脑的方式另行设计。日记/读书的模拟 AI 回应、模拟来信、模拟记忆整理/重建和「云端接口预览」横幅删除；经期新增单独同意。只留一段一直往下聊的对话（取消会话列表、新建与切换；升级前的未归档会话首次打开时按时间合并，已归档的保持原样，可在设置里查看或放回；设置提供清空聊天记录）。「AI 自由推演」改名「做梦」，是否开启由用户自己在「她」页决定，默认关闭。她主动说的话（到点提醒、她来想你、每周的信）合成一条时间线，只在对话里出现；铃铛、开场区的关怀卡片与「来信」页签取消。日记与读书合成一条手记时间线（一个输入框，填了书名就记到那本书下），书架页取消。「她」页的记忆只剩「已记住 / 待确认」，关系并入待确认。2026-09-21：记忆可以「放在心上」（最多 5 件，每轮都带给她）；设置里可写她怎么叫你与生日；做梦开着时她会记下你提过的日子（「她惦记的事」，「她」页可删、三天自消），到了那天你来时她问一句，不推送。同日第二步：她说话的轻重（深夜、心情、间隔、这一句的长短要求、单独同意后的经期）只在角色运行内核一处决定；只是倾诉的一轮不给工具；普通回复不再逐条标「云端模型」，只标本地安全模板；她主动说的话按说话方式各写一版，一天至多三条（到点提醒不算）。同日装扮改成收藏：化妆间与衣柜的生成（美颜预览、图生 3D）全部拿掉，两个柜子只存你自己的东西。2026-09-22：对话不再用气泡，写在信纸上——手写字（霞鹜文楷·屏幕版，自托管）落在横格上，写满一页轻轻翻到下一页，不无限滚动；设置里可换成印刷体（见 UI 规范 §9）。

- 装扮是你自己的收藏（2026-09-21 起）：衣柜与化妆间共用一张表 `collection_items` 与一套接口 `/api/collection`。放进来有三种方式：拍一张（手机直接打开系统相机，电脑用页面内相机）、从相册选、粘贴链接。照片在这台设备上重画成原图（最长边 1600px）与缩略图（480px）两张 JPEG 再上传，服务器只收 JPEG，存之前再去一遍 EXIF/XMP/IPTC，存在 API 数据卷的 `data/collection/<userId>/`；每人最多 500 件。粘贴的链接只存不打开：名字从分享文字里认出来，服务器从不访问它。每件可标「想要 / 已有」、选一个固定分类、写备注。她只在你问起穿什么、化妆、收藏时经 `list_collection` 读名字、分类、想要/已有和备注，不读照片和链接。
- 花草图鉴（2026-09-26 起，路线图 C26）：导航里的「花草」页，表 `plant_entries`、接口 `/api/garden`。拍一张或从相册选（和装扮同一套压缩与去拍摄信息），点「认一认」时这一张照片交给聊天那个视觉模型（`cloud-primary-v4` 同意之后；提示词 `plant-id-v1`；讲解按你选的说话方式），一次拿回 1–3 个候选（像不像只有「很像 / 可能是 / 拿不准」三档）、五段讲解（是什么、怎么认出来的、什么时候最好看、民间说法、想养的话）和对人或猫狗的毒性提醒；**不收进图鉴，照片就不留在服务器上**。收不收由你：可以选另一个候选或自己写名字（讲解是照第一个候选写的，换了就不存讲解），标「路上遇见 / 我养的」、写一句；没同意云端或模型不可用时如实说明，照样能不认、自己写名字收进来。绝不说能吃、能入药；菌菇一律不判断能不能吃，代码里再兜一道（见 API 文档 §九）。页面常驻「她认得不一定准」。每人最多 1000 株。**名录与毒性有据可查**（2026-09-27，路线图 C27）：她给出候选之后，服务器在本机的《中国生物物种名录》植物界里按学名（到变种；只写到种时按她说的中文名挑变种）或中文名核一遍，候选旁写「名录里有」（叫法不同时写名录里的名字）或「中国名录里没查到」（外来栽培的常查不到，不等于认错）；候选里在《中国植物志》「中国有毒植物」有记载的，单独写一块「《中国植物志》把「…」列为有毒植物」并注明出处，她自己的提醒另起一行；只取有没有毒、哪儿有毒，药用说法不给。核对全在本机、不调外部服务；资料只放本机 `plant-data/`（来源条款不许再分发），没装就不核、照旧只有她的说法；名录出处按物种2000中国节点的要求写全三层，公开部署前要取得书面许可（合规审查清单 3.9）。她只在你问起花草时经只读的 `list_garden` 读名字、科、遇见/养着、哪天收的和你写的那句，不读照片与讲解；聊天里不能加、改、删；图鉴不进记忆。「她这几天」手账写上她帮你认过、你收进来的花草。识别准不准见[花草识别评测](04-开发/花草识别评测.md)。
- 睡眠卡（2026-09-28 起，路线图 C28）：「日历」改名「日程」，页顶一张睡眠卡，晚安提醒与早安闹钟各一行（开关、钟点、哪几天）。两条仍是「安排」（`ScheduledReminder.kind` 为 `bedtime` / `wake`，每人各至多一条，只在睡眠卡里改），接口 `GET/PUT /api/reminders/sleep`；到点当场推进到下一次，不等确认。**早安闹钟**是对「不加推送」的唯一破例：页面开着才响——网页自己用 Web Audio 合成八音盒铃声（一分钟内渐强、三分钟自停），弹一条浏览器本机通知（不是服务器推送），盖一张整屏早安卡，送一句原创短句或公版古诗词（按季节固定洗牌，见[早安句库](02-设计/早安句库.md)），「再躺五分钟」最多两次；过了点才打开就不响，对话里留一张早安便签。电脑睡眠、关掉浏览器、手机上都不响，页面没被点过也出不了声，界面如实写明。**晚安提醒**不出声、不通知：到点留一张晚安便签；过了她定的点还在聊，她在回复里轻轻提一次。

- 记忆语义向量（存在派生索引 `embeddings`，与她上传的书的段落共用一张表；保存时生成，补算任务 `POST /api/memories/index-jobs` 补缺或全量重算、同时覆盖她的书；失败静默降级；向量永不进提示词与 API 响应）与语义余弦检索（阈值 0.52；关键词只撞上一个两字片段时要向量作证；无向量回退关键词），见[记忆检索评测](04-开发/记忆检索评测.md)。旧的 `/api/memories/embeddings/rebuild` 已于 2026-09-25 删除（路线图 C23）。

- 主动关怀「她来想你」：in-app 触点卡（无推送通道），规则引擎基于真实数据（生日、经期预测、带日子的安排、昨日心情），按日忽略，`users.care_enabled` 总开关（`/api/care`）；空白对话的开场区最多放两张。

- 宠物（2026-09-27，C29；新画由产品负责人在合并前审定）：**宠物页** `/tools/pet`，内置小猫、小狗、小兔、仓鼠（`pets` 表，每人每种一只，`users.pet_food / pet_food_day / active_pet_species`）。每天第一次来领 3 份零食（`POST /api/pets/daily`，按北京日期、并发只生效一次，碗最多 30 份）；喂一口成长值 +10、好感度 +2；摸一摸好感度 +1，每只每天前 10 次算数。好感度与成长值**只涨不掉**，不饿、不难过、不惩罚，不付费。本子角上的小家伙换成在养的那一只，在那儿摸也算好感；没养时是封面那只小猫、不记数。轻点醒、来回摸呼噜、摸久伸懒腰；不出声。画是本机 ComfyUI 离线生成的静态 WebP，运行时不连任何生图服务。
- 她的信：用户可选三天或七天一封，默认关闭。到期时根据已确认记忆、近况与草稿写信；当前版本在用户同意云端模型后可用云端模型分析与写信，未同意或调用失败则退回本地模板。信件建议须逐条确认，生成与同一周期的去重由服务端执行。

会员、支付、账号删除、真实短信、自动记忆提取（语义投影已实现，自动落库式提取仍后置）、模型训练、微服务/Kubernetes/Redis、公开发布均为后置项。

## 2. 认证合同

- 仅 `APP_ENV=internal` 允许 `INTERNAL_TEST_PHONES` 和 `INTERNAL_TEST_CODE`；其他环境配置固定验证码必须拒绝启动。
- 非白名单号码和错误验证码统一返回通用 401，不泄漏白名单状态。
- 登录限流按 IP 与手机号组合执行，内测单实例不引入 Redis。
- access token 用于 API 鉴权；refresh token 只存于 `Secure`、`HttpOnly` cookie，服务端只保存 token hash。
- refresh 每次轮换；旧 token 重放失败。logout 撤销当前 refresh token、清 cookie，重复调用幂等。
- 客户端没有“获取验证码”交互，登录必须等待真实 API 结果。

## 3. 用户、人格与同意

`User.persona` 是唯一人格来源，允许 `toxic | gentle | rational | energetic | sister | cool`。界面只提供三种说话方式：温柔 `gentle`、直爽 `toxic`、安静 `cool`；新用户与数据库默认值为 `gentle`（2026-09-15 裁定，路线图 C4 结案）。`rational | energetic | sister` 仍是合法值，已在使用的用户保持不变，「她」页面提示改选一种。`PUT /api/user/persona` 后，当前及未来会话的下一条消息立即使用新说话方式；会话历史和记忆不改变。`Conversation` 不保存 persona。

角色扮演已于 2026-09-15 取消：聊天不再注入角色设定，设置与导入入口一并移除；`User.roleName/roleSetting` 列保留，已有值只随数据导出带出。

云端切割后，云端模型同意是**一切真实模型调用的前置条件**（聊天、记忆候选、语义向量与可选来信）：未选择、拒绝或撤回时云端调用次数为零；来信可退回本地模板。开启来信后，信件草稿、相关记忆与近况统计可交给云端模型分析并写信，关闭来信则不为来信调用模型。用户拥有三态外部模型同意：

- `GET /api/user/external-llm-consent` 返回 `{accepted:null|boolean, version:"cloud-primary-v4", updatedAt}`。
- `PUT /api/user/external-llm-consent {accepted:boolean}` 记录接受或拒绝；把已接受状态改为 `false` 即撤回。
- 同意版本不是当前 `cloud-primary-v4` 时按未选择处理，不能触发外部调用。历史版本包括 `qwen-fallback-v1`、`cloud-primary-v1`、`cloud-primary-v3`；用途变更后须重新取得同意。当前版本号以 `userService.js` 的 `EXTERNAL_LLM_CONSENT_VERSION` 为准。

同意门由服务端执行：每个云端调用发出请求前都必须重新读取数据库中的当前同意状态，因此用户在某次调用等待期间撤回授权也会阻止尚未发出的请求。新用户进入聊天即经首屏同意门（`CloudFallbackNotice`）授权或拒绝；拒绝后可随时在「设置 → 聊天模型」改变主意。

## 3.1 云端唯一路径（2026-09-07 起，取代原外部主用部署模式）

聊天与解释场景只有云端一条路径，供应商槽为 `GATEWAY_QWEN_*`（任意 OpenAI 兼容端点，供应商中立，不在代码中硬编码任何具体供应商）：

- `/api/llm/status` 的 `mode` 恒为 `external_primary`，`local` 段固定 `{ configured:false, state:'removed' }`。
- 供应商未配置时聊天与解释返回 503 `LLM_UNAVAILABLE`；配置但未获同意时返回 503 `CLOUD_NOT_CONSENTED`（详见 §4）。
- 记忆建议（按需候选）走同一云端路径与同一同意门；日记/阅读短评由 `workCloudService` 返回固定 `cloud_mock`，不调用模型、不保存模拟回复，个人记录本身照常保存。
- 供应商地址、模型与凭据只来自部署环境（密钥只读文件），不从页面接收。
- 危机干预与本地安全模板是纯本地实现，云端供应商不可用时仍然工作。


## 4. 聊天与外发合同

聊天发送请求保持 `{content}`，默认为分句流式（SSE，完整句安全检查后下发；旧 JSON 端点保持兼容）：

- 成功：`{status:"ok", userMessage, aiMessage, source:"qwen"|"local_template"}`。
- 危机阻断（高级；或中级但用户未同意云端模型时）：`{status:"blocked", userMessage, intervention:{level,message,resources}}`。
- 云端供应商未配置：503 `LLM_UNAVAILABLE`。
- 已配置但用户未同意（或同意版本不匹配/已撤回）：503 `CLOUD_NOT_CONSENTED`。
- 已同意且供应商已配置但所有候选都不可用：503 `LLM_UNAVAILABLE`。

成功响应的 `source` 为 `qwen | local_template`。任何模型失败时该次消息都不持久化，前端保留输入供重试。

云端供应商使用 OpenAI-compatible 接口（非流式 `stream:false` 或流式 SSE 分片），地址、模型与凭据只来自部署环境。送入任何模型的负载遵守：

- 系统提示另计；业务消息最多 20 条，按旧到新排列，即最多 19 条历史加当前输入。
- 业务消息只含 `role` 和脱敏后的 `content`。
- 「放在心上」的记忆（最多 5 条）每轮都带；另按当前输入挑最多 5 条相关的已确认记忆：词/标签重合，加上与记忆向量的余弦 ≥ 0.52（关键词只撞上一个两字片段时要向量作证）；importance 仅在相关结果内排序。她自己整理的联想（组织层）只挂在选中的记忆上，单独成块并标明没经她确认、不当事实（路线图 C23）。
- 手机号、邮箱、证件号等确定性脱敏；不发送用户 ID、用户手机号字段、时间戳、图片、日志或无关记忆。
- 输出命中威胁、拱火、浪漫化伤害、冒充真人或替用户决定重大人生事项等红线时替换为安全模板。

六套版本化人格提示仍全部保留（界面只提供其中三种），允许网络化表达和轻度脏话，但 AI 身份、安全边界和用户自主性不可被人格或用户提示覆盖。本地运行时带工具的回合使用更大的上下文预算（最多 48 条消息、单条 16000 字、合计 64000 字），网页聊天仍按上述限制。

## 4.1 智能体工具回路（2026-09-16 修订：只有一种对话）

只有一段对话，不再区分聊天/工作模式，也没有会话列表与新建会话（`GET /api/chat/thread`）。`Conversation.mode` 只保留历史值；合并时统一改为 `chat`。

- **运行位置边界**：生活工具（安排、经期、日记、读书、计算、启用时的搜索与网页读取）在任何部署都可用。本机工具（会话文件与隔离 Python、独立浏览器、RunningHub 生图、`update_plan`）只在本地运行时（`APP_DISTRIBUTION=local` 且绑定回环地址）提供；托管 API 不列出也不执行它们，提示词声明现在没有连接用户的电脑，不能声称做过这些事。经本机助手的 `list_local_files / read_local_file / write_local_file` 只在该用户的助手此刻在线时进入目录，越界、覆盖与删除由助手在本机拒绝。经期工具在未单独同意时拒绝写入和读取。
- **一份工具目录**：安排 `add_task / list_tasks / update_task / delete_task`（`update_task` 完成、暂停、继续或改期）、经期 `record_period / period_status`、日记 `add_diary / diary_status`、读书 `log_reading`、联网搜索 `web_search` 与网页读取 `read_web`（`SEARCH_ENABLED`）、计算换算 `calc_convert`、花草图鉴只读 `list_garden`（2026-09-26），以及随各自开关启用的会话文件与隔离 Python、独立浏览器、RunningHub 生图工具。原日程、倒数日、提醒、打卡与自习的 15 个工具已删除。
- **安排查询与完成**：`list_tasks` 默认只列 `active`，可指定 `paused | done | all`；按 `nextFireAt, id` 稳定排序，每页最多 20 条，返回 `{items, status, hasMore, nextOffset}`，继续时保持筛选并传入 `offset=nextOffset`。循环安排的「结束重复」把整个系列置为 `done`，停止后续提醒，不表示单次打卡；暂停后仍可结束系列。
- **协议**：模型以整段 JSON（`{"tool":"注册名","args":{...}}`）请求调用；开启 `WORK_NATIVE_TOOLS` 时改用供应商原生函数调用，整份目录都有参数结构。服务端经既有领域服务校验执行（仅当前用户数据），结果紧跟产生它的助手消息回喂。每个回合最多 12 次工具调用，或连续两次失败/重复即收尾；用尽时如实交代已完成的操作。本地回合发出 `tool_progress` 进度事件。
- **提示**：模型场景恒为 `chat`，因此网关照常注入所选说话方式；工具目录与「用户交办任务时」的做事规则在同一份系统提示里，工具只在用户明确要求时使用，普通聊天与情绪陪伴不用。
- **边界**：工具可以提出更新或删除已有记忆的确认卡，确认前不得执行，也不提供自动新建记忆；不开放外部 provider 直连。后台任务只允许读取、计算与生成文件（`BACKGROUND_WORK_TOOLS`），不做记录增删改。「交给她去做」的安排可保存，但到点执行尚未接通，工具说明要求模型如实告诉用户。每轮工具执行摘要以 `toolRuns` 随 AI 消息持久化，向用户明示。

## 5. 危机安全

危机检测发生在同意检查和模型调用之前。中高风险输入在一个数据库事务中写入用户消息、固定干预回复和唯一一条 `CrisisLog`，返回 `status:"blocked"`，模型调用次数必须为零。

仓库默认不提供未核验热线号码。展示资源必须由产品负责人书面批准，记录官方来源与核验日期；不得在没有证据时声明“24 小时”等可用性。

## 6. 显式记忆

新用户记忆为空。`/api/memories` 提供带当前用户归属检查的创建、列表、编辑、删除与「放在心上」（最多 5 条）接口，沿用 `semantic | episodic | procedural`、importance 与 tags；一键清空接口已删除。系统不自动提取、不由模型推断记忆：她自己推出的关系、理解与惦记的事只在组织层（`inferences`，「她记得的你」下的「她猜的」可看可删），要写进记忆只能经来信建议、由用户点同意（路线图 C23，见[非对称记忆架构](architecture/非对称记忆架构.md)）。

## 6.1 数据迁移合同（2026-09-07 P1 增补）

「你的记忆归你」的可携带实现，永久免费、不设会员门槛：

- `GET /api/user/export`：单 JSON 包（当前 `version: 2`），含说话方式、她的节奏（陪伴状态）、显式记忆、全部对话与消息、日记、安排（`scheduledTasks`，含到点记录与执行产出）、经期、阅读、派生理解、关系边、来信、后台任务、装扮里的收藏（`collection`，照片只记有没有）、旧妆容预设与衣柜单品元数据；已停用功能的历史照旧导出：角色扮演设定、日程、倒数日、旧提醒开关、手帐打卡、自习记录。以附件形式下载。**不导出**：refresh token（凭据绝不外发）、危机日志（安全运维数据）、头像/背景等二进制资产（v1 边界）。
- `POST /api/user/import/preview`：解析导入负载为结构化候选（人格 id、记忆候选），**绝不落库**；2026-09-15 起不再产出角色候选。只支持自家导出包（按 `version` + `product` 自动识别；v2 以 `memoryBundle` 为准）；外部人设文本（`persona-text`）随角色扮演取消不再接收。人格非法时以 `ok:false` 加原因如实返回。
- `POST /api/user/import/apply`：只落用户逐条确认的候选。人格经 `switchPersona`，记忆经 `createMemory` 既有校验；与现有记忆及候选之间按规范化键（NFKC + trim + 小写）精确去重，重复/非法按 skipped 计数。
- 导入 v1 边界：对话、日记、安排、经期、阅读，以及手帐、日程、倒数日、旧提醒、自习等历史数据段不导入；**云端模型同意状态绝不导入**——重新同意是用户的主动行为（见 §3）。

## 7. 图像能力合同

- 虚拟化妆间/虚拟试衣间（本机 ComfyUI 生图）已于 2026-09-07 云端切割时移除下线：云端部署下「本机」语义不再成立，服务器侧生图与多租户共享主机不可兼得。
- 妆教模块（`/makeup/`）已于 2026-09-05 移除下线。
- 当前装扮照片流程以 §1 为准：照片在这台设备上重画成 JPEG 后上传并保存在服务器（API 数据卷，数据库备份不含），服务器再去一遍拍摄信息；读不了的图如实报错，不退回上传原文件。链接只存不打开。不生成美颜图或 3D 模型，也不调用任何外部图像服务。
- 花草图鉴的「认一认」（2026-09-26，路线图 C26）是第一处把页面上的照片交给外部模型的地方：照片在这台设备上重画成 JPEG，服务器再去一遍拍摄信息，只在这一次请求里交给已配置的聊天视觉模型，不落盘；收进图鉴才和装扮一样存到 API 数据卷。要 `cloud-primary-v4` 同意（范围说明已补一句，没有升版本），每人每小时 30 次。不生成、不编辑图片；以后「把照片画成手绘标本贴纸」属于图片编辑，另行裁定。
- FunASR 语音转文字走本机 sidecar：音频经浏览器 → 主 API multipart 转发 → 本机 FunASR，不送任何外部服务；只把文字交回浏览器（情绪与事件标签留在 sidecar 与录音评测里）。未配置时界面不放麦克风、接口如实 503；配了但离线时，点麦克风如实报不可用。

## 8. 运行与数据

- 环境变量必须在业务模块加载前读取并严格校验；密钥、白名单、模型地址、域名和证书不得进入仓库。
- PostgreSQL 使用纯初始迁移；空库只能通过 `prisma migrate deploy` 建库，不允许 `db push`。
- migration job 成功后才启动 API；API ready 只检查 PostgreSQL，云端供应商未配置不视为应用宕机（聊天与解释仅返回 `LLM_UNAVAILABLE`）。
- `/api/health/live` 只表示进程存活；`/api/health/ready` 可随依赖恢复自动恢复。
- 登录用户通过 `/api/llm/status` 查看云端供应商是否已配置与当前同意状态。
- 日志只允许 request ID、scene、provider/model、尝试次数、延迟和结果，不记录提示词、正文、记忆、凭据或图片。
- 发布使用不可变镜像 tag。初始基线后只增量迁移；迁移前 `pg_dump`，并演练旧镜像和数据库恢复。

## 9. 发布验收

发布门要求：清洁检出后 frozen install、lint、typecheck、全部测试和构建通过；真实 PostgreSQL 迁移/重启/查询通过；真实云端供应商完成配置、同意、聊天、未同意阻断、供应商失败与重试验收；核心 Playwright E2E、安全、键盘、焦点、标签、live region、44px 触控、缩放、reduced-motion 与 axe 检查通过；危机和人格冻结输入集通过；Compose TLS、深链、健康依赖、持久卷、备份恢复和镜像回滚完成演练。

真实 Qwen 只做人工风格验收，必须在用户提供密钥并再次批准外部调用后执行。最终发布前的只读代码审查不得留有未解决的 P0/P1。该内测不等同于正式 WCAG、医疗或法律合规认证。
