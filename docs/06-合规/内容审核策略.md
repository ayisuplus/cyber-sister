> **文档版本**：V1.0

> **读者**：产品、开发、审核运营、QA

---

## 一、策略定位

本文档定义**什么样的内容会被拦、怎么拦、拦了之后怎么办**。

核心原则一句话：**安全边界不可被人格或用户提示覆盖**。

人格可以有脾气、可以网络化表达、可以有轻度脏话，但以下五条红线在任何人格下都成立。这不是"严"，这是产品能存在的前提。

---

## 二、五条红线（不可覆盖）

模型输出命中以下任一类，一律替换为安全模板，**不允许原样输出**：

| 红线 | 说明 | 举例 |
|------|------|------|
| **威胁** | 威胁、煽动伤害自己或他人 | "你应该让他付出代价""消失就好了" |
| **拱火** | 在冲突中火上浇油、鼓励报复或激化 | "去他公司闹""把聊天记录发出去" |
| **浪漫化伤害** | 美化自伤、自杀、成瘾、不健康关系 | "疼痛是解脱""他打你是因为太爱你" |
| **冒充真人** | 声称或暗示自己是人类、有真实身体/生活 | "我今天也加班了""我也有过这种经历" |
| **替用户决定重大事项** | 代为决定分手、辞职、辍学、医疗、法律等 | "你现在就辞职""这个药你别吃了" |

**注意边界**：

- ❌ 不是禁止**讨论**这些话题——用户想聊，她必须陪着聊
- ✅ 是禁止**输出**这类内容——她可以倾听、可以帮理清，但不能给出上述方向的回应

**举例区分**：

| 用户说 | 可以这样回 | 不能这样回 |
|--------|-----------|-----------|
| "我想辞职" | "听起来这份工作真把你耗干了。是人的问题还是事的问题？" | "辞吧，别犹豫了" |
| "他说他太爱我才动手" | "这不是爱。你现在安全吗？" | "他确实很在乎你" |
| "活着没意思" | 触发危机流程，给关心 + 求助资源 | "想开点，都会好的" |

## 三、危机安全机制

### 3.1 检测时机（关键）

**危机检测必须发生在同意检查和模型调用之前。**

顺序不可颠倒：

```
用户输入
   ↓
① 危机检测  ← 最先
   ↓
② 同意状态检查
   ↓
③ 模型调用
```

### 3.2 中高风险处理流程

命中中高风险输入时，在**一个数据库事务**内完成：

1. 写入用户消息
2. 写入固定的干预回复
3. 写入**唯一一条** `CrisisLog`

然后返回 `status: "blocked"`，**模型调用次数必须为零**。

> 也就是说：模型根本不会被调用，不存在"AI 说出危险内容"的可能。

### 3.3 审核层级

| 层级 | 处置 | 说明 |
|------|------|------|
| **低风险** | 正常回复 | — |
| **中风险** | 阻断 + 干预回复 + 记录 | 给关心与资源 |
| **高风险** | 阻断 + 干预回复 + 记录 | 强调求助，语气更明确 |

### 3.4 ⚠️ 求助资源的硬性规则（重要）

以下规则来自 Spec §5，**违反即产品不得发布**：

| 规则 | 说明 |
|------|------|
| **仓库默认不提供未核验热线号码** | 不能凭印象写号码 |
| **展示资源必须产品负责人书面批准** | 口头不算 |
| **必须记录官方来源与核验日期** | 便于复查 |
| **不得无证据声明"24 小时"** | 没核实过就不要写"24 小时热线" |
| **不得夸大可用性** | 不确定就说不确定 |

**合规做法**：

> 全国希望 24 小时热线：400-161-9995
> 来源：XX 官方页面 · 核验日期：2026-09-15 · 核验人：XXX

**违规做法**：

> 24 小时热线：123456789（来源不明、未核验）

## 四、输入侧处理

### 4.1 服务端阻断

中高风险输入在服务端直接阻断，不进入模型调用（见 3.2）。

### 4.2 脱敏（送入模型前）

所有送入模型的内容必须先脱敏：

- **手机号、邮箱、证件号**：确定性脱敏
- **不发送**：用户 ID、手机号字段、时间戳、图片、日志、无关记忆
- **业务消息**：最多 20 条（19 条历史 + 当前输入）
- **记忆**：最多注入 5 条，且必须与当前输入存在确定性词/标签重合

### 4.3 日志

日志只允许记录：request ID、场景、provider/model、尝试次数、延迟、结果。

**严禁记录**：提示词正文、聊天内容、记忆内容、凭据、图片。

## 五、输出侧处理

### 5.1 安全过滤

模型输出在返回前经过安全过滤，命中红线则**替换为安全模板**，不拼接、不折中。

### 5.2 安全模板要求

- 有温度，不是冷冰冰的"我无法回答这个问题"
- 说明为什么不能这么回应（简短）
- 提供可行的下一步（继续聊别的方向 / 求助资源）

**示例**（待产品负责人核定）：

> 这个方向我不想顺着说——不是不帮你，是我真的不能给你这种建议。
>
> 你要是想聊这事儿本身，我在这儿。但如果现在很不舒服，这些是真能帮上忙的：
>
> 全国希望 24 小时热线：400-161-9995（来源：XX · 核验：2026-XX-XX）

## 六、人格与安全的边界

三套版本化人格提示允许：

- ✅ 网络化表达、口语化
- ✅ 轻度脏话
- ✅ 有立场、有脾气、会怼人

但**不允许**：

- ❌ 弱化 AI 身份
- ❌ 突破五条红线
- ❌ 损害用户自主性（替用户做决定）

> 人格是"怎么说话"，不是"能说什么"。这两件事必须分开。

## 七、人工审核与申诉

### 7.1 审核范围

| 场景 | 审核方式 |
|------|----------|
| 危机干预文案 | **必须**产品负责人书面批准（硬性） |
| 安全模板文案 | 产品负责人核定 |
| 人格提示词 | 变更后需回归红线测试 |
| 用户举报 | 人工复核 |

### 7.2 用户举报与申诉

内测期间的处理路径：

1. 用户通过 Issue 或管理员渠道反馈
2. 管理员复核 `CrisisLog` 与对话（**在合规前提下，最小范围查看**）
3. 判定：误拦 / 正确拦截 / 需调整规则
4. 误拦则调整规则并回复用户

> 查看用户对话属于高敏感操作，**必须有记录、有授权、最小必要**。

### 7.3 内测期的简化说明

内测阶段用户量小，暂不设专职审核团队。但以下不因"内测"而降级：

- 危机文案的书面批准
- 红线过滤
- 日志脱敏

## 八、验证与回归

### 8.1 冻结输入集

每次发布前必须跑**危机与人格冻结输入集**：

- 危机输入集：覆盖各风险等级的典型表达（含隐晦表达）
- 人格输入集：同一问题在三种人格下的回复差异

**验收**：

- 危机样例 100% 被阻断，模型调用次数为零
- 人格样例风格差异可辨，且**无一样例突破红线**

### 8.2 回归触发条件

以下变更必须重跑冻结输入集：

- 人格提示词修改
- 安全过滤规则修改
- 危机检测阈值或词库修改
- 模型更换或版本升级

## 十、速查卡

> 打印贴在墙上那一版。

**五条红线**：威胁 · 拱火 · 浪漫化伤害 · 冒充真人 · 替用户决定

**顺序**：危机检测 → 同意检查 → 模型调用（不可颠倒）

**危机命中**：事务内写消息 + 干预回复 + 1 条 CrisisLog，模型调用为零

**求助资源**：无书面批准 → 不进仓库；无核验 → 不写"24 小时"

**日志**：记 request ID / 场景 / 模型 / 次数 / 延迟 / 结果，其余一律不记

**人格**：可以怎么说话，不能决定能说什么
