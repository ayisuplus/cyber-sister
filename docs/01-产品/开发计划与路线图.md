## 0. 本文档的定位

2026-09-15 追加用户目标：优化工作模式，对标旗舰 Agent 通用能力并保留 Amie 角色特色；多模态比较 RunningHub 云端 API 与替代方案。第一批交付为真实工作对话、任务步骤、文件产物与取消边界；第二批打通文件上传/解析、网页正文与来源、隔离 Python、Office/PDF 和 Dots 原生工具；第三批实现显式后台任务、租约/检查点、页面恢复、重启与取消，真实 Dots 在隔离 API 重启后继续交付 CSV；第四批完成临时容器自动删除、到期回收和真实进程崩溃验证；第五批完成独立 Chromium 的匿名网页操作、动态正文、真实截图与模型端到端交付；第六批完成实际请求预览、用户逐次确认和提交后的结果核对，崩溃恢复禁止重发不确定操作，真实 Dots 提交回显验收通过。账号登录、跨域、连接器、生产隔离、周期调度及多模态实测仍待实施。用户改为要求自建 RunningHub 工作流并优先开源模型；Z-Image Turbo 生图与 Qwen 2511 参考图编辑已实测成功，合计消耗 54 RH 币，现已接入工作 Agent 的后台逐次确认、云端编号保存、图片取回和会话预览，API 1053、Web 732、独立 PostgreSQL 61 项回归通过；本地密钥已配置，真实 API 鉴权及旧任务查询通过，新建生成 API 和更多场景效果待验收，见[自建图像工作流](../09-参考/历史归档/runninghub-workflows-20260915.md)。验收与选型依据见[工作 Agent 与多模态选型](../09-参考/历史归档/work-agent-20260915.md)、[后台任务](../09-参考/历史归档/background-tasks-20260915.md)、[网页操作](../09-参考/历史归档/work-browser-20260915.md)和[外部提交确认](../09-参考/历史归档/work-actions-20260915.md)，不以阶段交付代替整体目标完成，也不变更发布承诺。

本文件是**执行层的排期与分工计划**，不是产品需求（需求看 PRD / Spec），也不是架构设计（设计看 architecture/）。它回答三个问题：

1. 接下来 4 周做什么、谁来做、什么算做完
2. 哪些是"边边角角"但必须做的工作（文档、合规、验收、一致性）
3. 发布前必须关闭哪些门

> 排期基于当前代码与文档状态推断，如与团队实际进度冲突，以每日站会结论为准并回写本文件。
