## 二、可并行推进的工作方向（按优先级排列）

### 🔴 P0 — 立即启动（关键路径，不依赖微调数据）

#### 2.1 数据预处理 Pipeline

**为什么是 P0**: 数据采集完成后，如果没有预处理 pipeline，还需要额外 2-4 周才能开始训练。

| 项目 | 说明 |
|------|------|
| **具体工作** | ① 设计统一数据清洗规范（去重、过滤低质量、敏感信息脱敏）<br>② 构建 小红书笔记 → QLoRA 训练数据格式的自动转换脚本<br>③ 实现 DPO 偏好对数据的半自动标注工具（LLM 辅助 + 人工校验）<br>④ 搭建数据质量评估指标（多样性、长度分布、话题覆盖度） |
| **预期产出** | `LLM/data_pipeline/` 下的完整预处理工具链 |
| **所需资源** | 1 名工程师，1-2 周 |
| **与微调衔接** | 数据采集完成后直接接入，**节省 2-4 周等待时间** |

#### 2.2 模型评估指标体系与测试框架

**为什么是 P0**: 没有评估框架，微调完成后无法判断模型质量，会导致反复迭代。

| 项目 | 说明 |
|------|------|
| **具体工作** | ① 定义评估指标体系：<br>&nbsp;&nbsp;- 自动指标：BLEU、ROUGE、PPL、BERTScore<br>&nbsp;&nbsp;- 人工评估：闺蜜感、共情能力、安全合规、对话连贯性<br>&nbsp;&nbsp;- 对抗测试：合规边界、角色一致性<br>② 搭建评估测试集框架（先用合成数据验证流程）<br>③ 实现 A/B 测试基础设施（base vs fine-tuned）<br>④ 编写批量推理 + 自动评分脚本 |
| **预期产出** | `LLM/evaluation/` 评估框架 + 测试集 + 自动化脚本 |
| **所需资源** | 1 名工程师，1-2 周 |
| **与微调衔接** | 微调完成后立即可用，避免"训完了不知道好不好" |

#### 2.3 vLLM 推理服务搭建与优化

**为什么是 P0**: 推理服务是微调模型上线的最后一道关卡，提前搭建可实现"热替换"。

| 项目 | 说明 |
|------|------|
| **具体工作** | ① 搭建 vLLM 推理服务（先用 base Qwen3-8B 验证）<br>② 实现模型路由逻辑（8B 处理 80%，72B 处理 20%）<br>③ 配置推理参数优化（temperature、top_p、repetition_penalty）<br>④ 实现流式输出（SSE）接口<br>⑤ 压力测试：验证 P95 < 200ms 目标<br>⑥ 推理成本测算（目标 ≤5 元/人/月） |
| **预期产出** | `Agent/services/llm-service/` 完整推理服务 |
| **所需资源** | 1 名工程师 + GPU 服务器，2 周 |
| **与微调衔接** | 微调模型产出后直接加载，**零等待上线** |
