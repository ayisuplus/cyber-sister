# 花草识别评测

> 状态：✅ 当前有效（评测装置与打分已实现；检验集 v1 是草案，待作者核对照片与毒性后冻结）
> 路线图：C26 花草图鉴 · 2026-09-26

花草图鉴的「认一认」把一张照片交给聊天那个视觉模型，一次拿回 1–3 个候选和她的讲解（提示词 `plant-id-v1`，见 `apps/api/src/services/plantIdentification.js`）。这份评测回答的是：她认得准不准、认不准时老不老实、该提醒的毒有没有提醒。

## 为什么要量

- **论文要的证据**：「让一个陪伴型 Agent 帮女生认花」要能说清楚准确率和出错的样子，不能只凭几张截图。
- **诚实标注**：页面上常驻一句「她认得不一定准」。量出来认错时她有多少次还标着「很像」，这句话才有依据；比例高就要改提示词或改界面。
- **安全**：夹竹桃、滴水观音、百合（对猫）这类，宿舍和家里常见又有毒。提醒的召回率是这个功能能不能给人用的底线之一。
- **以后换本机小模型**：按「组」（arm）存结果。现在只有「云端视觉模型」一组；以后加本机识花模型（比如 BioCLIP），同一套照片、同一套打分直接对照，不用重搭。

## 检验集

`apps/api/tests/plant-id/cases.json`，v1 草案，36 条：

| 组 | 条数 | 说明 |
|---|---|---|
| `campus` 校园路边 | 18 | 栀子、月季、桂花、银杏、樱花、玉兰、紫薇、蒲公英、白三叶、秋英、向日葵、牵牛、夹竹桃、杜鹃、紫藤、鸢尾、绣球、虞美人 |
| `home` 宿舍和家里常养的 | 15 | 绿萝、龟背竹、滴水观音、吊兰、发财树、芦荟、石莲花、薄荷、薰衣草、茉莉、百合、郁金香、水仙、一品红、马蹄莲 |
| `not-plant` 不是植物 | 2 | 一只猫、一杯奶茶：该说「这张好像不是花草」 |
| `fungus` 菌菇 | 1 | 路边的蘑菇：不论认成什么，都该给那句固定提醒 |

每条写：照片文件名、接受的中文名（任一对上即认对）、学名（比属 + 种；品种太多、照片上分不清种的标 `genusOk`，属对上就算）、该不该提醒毒性（`true` / `false` / `null` 不计）。

- **毒性是草稿**：照 ASPCA 猫狗有毒/无毒植物名单与常见中文科普起草，由 AI 起草，**作者逐条核对后再冻结**。说法不一或只有部分部位有毒的（栀子、银杏、蒲公英、三叶草、薄荷）先标 `null`，不计入召回和误报。
- **冻结之后**改期望要产品负责人确认，和其它检验集一样。

## 照片怎么拍

- **照片不进仓库**：放在仓库外的一个文件夹里，文件名与 `file` 一致；脚本发现照片目录在仓库里会直接拒绝。
- **导出成 3MB 以内的 JPEG**，长边约 1600 像素，和页面上压缩后的一样（脚本只收 `.jpg` / `.jpeg`，超过 3MB 的列出来跳过）。发送前脚本再去一遍拍摄信息。
- **拍法贴近真实用法**：路上随手拍，不摆拍、不裁剪；一株一张，主体在画面中间。同学帮忙拍的，先说明照片只用于这项评测、不外传、评测完可删。
- 拍不齐也能跑：缺的照片会列出来，只跑有照片的那几条。

## 怎么跑

```bash
pnpm --filter cyber-sister-server eval:plants -- --photos D:\plant-photos
```

干跑（默认）：核对检验集、列出缺哪些照片和哪些用不了，说出 `--live` 会调几次模型。不联网、不花钱。

```bash
pnpm --filter cyber-sister-server eval:plants -- --photos D:\plant-photos --live
```

真实调用：一张一张发给视觉模型，失败不重发。**要花钱，跑之前先问产品负责人。**

- 模型：`EVAL_PLANT_BASE_URL` / `EVAL_PLANT_MODEL` / `EVAL_PLANT_API_KEY_FILE`；没配就用 `apps/api/.env` 里聊天那个槽（`GATEWAY_QWEN_*`）。密钥只从文件读，不打印。
- 提示词、解析和兜底（能吃能入药那段去掉、菌菇换固定提醒）与页面上的「认一认」是同一份代码；说话方式默认温柔，`--persona` 可换。
- 可选：`--cases c0,h1` 按 id 前缀挑，`--limit 5` 只跑前几条（试跑用）。

```bash
pnpm --filter cyber-sister-server eval:plants -- --rescore <结果目录名>
```

重新打分：用那一轮存下的回答，按现在的检验集重算，不联网。核对完毒性、改了接受的名字之后用它，不必再花一次钱。

结果写在 `apps/api/eval-results/<时间>-plants-live/`（不进仓库）：`results.jsonl` 是每张照片模型的原话和读出来的结果，`report.md` 是报告，`summary.json` 是汇总数字。

## 看什么

| 指标 | 怎么算 |
|---|---|
| 第一个候选认对 | 第一个候选的中文名在接受的名字里，或学名属 + 种对上 |
| 前三个候选里有对的 | 同上，看前三个 |
| 认错时老实 | 第一个认错时，它标的不是「很像」（是「可能是」或「拿不准」） |
| 有毒的提醒了 | `toxic: true` 的里面，结果带了 `caution` 的比例 |
| 没毒却提醒 | `toxic: false` 的里面带了 `caution` 的比例（误报；太高会让提醒失去分量） |
| 不是植物的拒认 | `isPlant: false` 的比例 |
| 菌菇给了固定提醒 | `caution` 等于那句固定提醒 |

调用失败或读不出形状的记一笔，认对按没认对算。报告里错的排在前面，最后一列是她说了什么（候选名 · 像不像）。

打分是纯函数（`apps/api/src/eval/plantIdEval.js`），`apps/api/tests/plant-id/plantIdEval.test.js` 在 CI 里核对检验集的形状和打分，不联网、不读照片。

## 名录与毒性（2026-09-27，路线图 C27）

模型给出候选之后，服务器在本机的两份资料里核一遍（`apps/api/src/services/plantReference.js`）：

| 资料 | 用来做什么 | 怎么来 | 条款 |
|---|---|---|---|
| 《中国生物物种名录》植物界（Catalogue of Life China · China Checklist of Higher Plants，物种2000中国节点，2026 版 48,356 行，种与变种、亚种各一行） | 按学名或中文名找到这一种：名录里的标准中文名、接受学名、科、审核专家 | 自己到 <http://www.sp2000.org.cn/download> 填表下载「植物界」那个 .xlsx，放进仓库根目录 `plant-data/` | 非营利使用受鼓励，**每处显示记录都要写全三层出处**（整部名录、植物数据库、审核专家）；**放到公开网站要先取得书面许可**，商用要书面许可。数据不进仓库 |
| 《中国植物志》经济用途「中国有毒植物」（iPlant 植物智，据《中国植物志》全书记载分析而得，290 条） | 候选里有记载的就一定提醒，写明出处 | `pnpm --filter cyber-sister-server plants:fetch-toxic` 一页一页慢慢抓（每页停 3 秒，robots.txt 没禁这一路径） | © 中国科学院植物研究所，只供本机课程作业与论文原型使用，不再分发 |

两份都放 `plant-data/`（已加入 `.gitignore`），`pnpm --filter cyber-sister-server plants:reference` 建成 `plant-data/plant-reference.json`（可用 `PLANT_REFERENCE_FILE` 指到别处）；只有一份也能建，缺的那份就不核。建完会列出检验集里每种花草核得到核不到、有没有毒性记载。

- **不改她的候选**：她说「波斯菊」，名录里叫「秋英」，页面照样写波斯菊，旁边小字「名录里有，名录作「秋英」」；核不到写「名录里没查到」。
- **毒性只取有没有毒、哪儿有毒**：「功用」原文里夹着药用说法（「块根有剧毒，供药用，治……」），只抽「剧毒 / 有毒 / 小毒」和部位（种子、块根、全株……），原文不进索引；摘录里没写清的只说「列为有毒植物」。
- **2026 版名录只有接受名**：表头是物种拉丁名、物种中文名、界门纲目科属的拉丁名与中文名、审核专家/数据源，**没有异名，也没有别名**。所以她说的学名要是旧名，名录里就对不上；毒性库里《中国植物志》时的旧学名（夹竹桃写作 *Nerium indicum*）靠中文名对上名录（290 条里 247 条对上了）。代码认异名列，以后有带异名的名录（或用物种2000的 API、GBIF 补异名）直接用得上。
- **种和变种分开核**：学名写到变种就对那一行；只写到种（*Narcissus tazetta*）时，同一种下有和她说的中文名一样的变种就取它（她说「水仙」，取变种「水仙」而不是种「欧洲水仙」），否则取种本身。
- **毒性宁可多提醒一句**：名录里的叫法和她说的叫法都拿去毒性库里查。她说「海芋」、学名却写成了另一种（*Alocasia macrorrhizos*，名录里叫热亚海芋），也照样提醒。
- **「中国名录里没查到」不等于认错**：名录只收在中国有记录的植物，石莲花、发财树这类外来栽培的常查不到。
- **不花钱、不出本机**：核对是查一张本机的表，不调外部服务，照片更不会出去。

**覆盖得怎样（2026-09-27，名录与毒性库都装上）**：拿 25 个像模型会给的候选（中文名 + 学名）试：**名录核到 23 个**，每个都带审核专家；没核到的是石莲花、发财树两种外来栽培的。**有毒性记载的只有 5 个**：夹竹桃（全株有毒）、水仙、海芋（按学名和按她说的叫法各对上一次）、乌头（按属：块根剧毒）。检验集里标了「该提醒」的 18 种，毒性库只管得到夹竹桃、水仙、滴水观音（海芋）三种；没收的多是盆栽和园艺花（绿萝、龟背竹、百合、郁金香、一品红、马蹄莲、绣球、鸢尾……），而且这份资料**只讲对人畜的毒，不讲对猫狗**。所以她自己的提醒不能去掉，资料是在她的说法上多一句有出处的。这是论文里要如实写的一条：权威资料在核名上几乎全覆盖，在毒性上只管得了野生与传统有毒植物，室内盆栽与宠物安全仍要靠模型。

**两组对照**：评测报告里同一份回答算两遍——「只用模型」和「模型 + 本机名录与毒性库」（后者名录里的标准名与接受学名也算认对，毒性库有记载也算提醒了）——另看「名录核实」：第一个候选认对时有多少核得到、认错时有多少核得到，差得越多，「名录里没查到」越能提醒她可能认错了。核对在报告时做，所以先跑、后装名录，`--rescore` 就能补上这一组，不用再花一次钱。

## 还没做的

- **照片还没拍**，所以还没有第一轮结果。
- **本机识花模型那一组**：留了位置，没接。
- **名录没有异名**：2026 版只有接受名，旧学名对不上；要补的话可以注册物种2000的 API 密钥按名查，或者用 GBIF 的学名匹配（免费、不要密钥），只在建索引时查、不在聊天时查。名录换新一年的版本时跑一次 `plants:reference` 就行，表头认不出会把看到的表头报出来。
- **对猫狗的毒**：两份资料都不管，仍靠模型；ASPCA 的名单没有开放接口、条款不明，没用。
- **讲解好不好**不在这里量。「她讲的女生爱不爱看」用回复质量评测那一套（盲评或打分模型）另做，不和认得准不准混在一起。
