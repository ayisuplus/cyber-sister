# 工作模式云端接口（2026-09-12）

状态：✅ 当前有效。依据本轮源码整理，供本地接口联调与前后端对接使用；不表示已连接真实云端，也不是发布验收结论。

机器可读契约：[工作模式云端接口-20260912.openapi.json](./工作模式云端接口-20260912.openapi.json)。它覆盖本轮新增或改变的接口，不重复整站所有既有 CRUD schema。服务基址为 `/api`，以下表格省略此前缀。

## 1. 执行与保存的边界

工作模式的生成能力固定在 mock 阶段。`workCloudService.js` 不读取供应商配置，`isWorkCloudConnected()` 固定返回 `false`，没有环境变量可以把这一轮接口误切到真实供应商。媒体预览也不调用真实云端、ComfyUI 或本地模型。

个人日程、习惯、打卡、日记、书架、笔记、经期、已确认自习、提醒等记录仍由既有鉴权 API 保存到数据库。**不入库的是模拟生成结果，不是这些个人记录。** 已有来信、理解和短评保留原来的读取与用户确认操作；新的模拟文本不作为它们的持久记录。

新的云端模拟结果使用：

```json
{
  "source": "cloud_mock",
  "execution": {
    "mode": "mock",
    "cloudConnected": false,
    "persisted": false
  }
}
```

各领域保留原来的返回形状，不能假设每个响应都有顶层 `source`：

| 场景 | 结果字段 | 模拟标识 |
| --- | --- | --- |
| 日记、读书、自习短评 | `aiComment`、`reused: false` | `source: cloud_mock` 与 `execution` |
| 手帐鼓励 | `cheer` | `source: cloud_mock` 与 `execution` |
| 工作台分析／重建 | `preview.content`，创建计数均为 0 | `skipped: cloud_mock` 与 `execution` |
| 生成来信 | `letter: null`、`created: false`、`preview.content` | `reason: cloud_mock` 与 `execution` |
| 美颜／衣柜预览 | `requestId`、`result` | `source: cloud_mock` 与 `execution` |
| 经期推算 | `asOf`、`nextDate`、`daysUntil` | `source: server_calculation`；没有云端执行 |
| 自习运行状态 | `status`、时间戳、`actualMinutes` | 单独的内存计时 `execution`，见第 3 节 |

本人记录已经有短评时，三个短评接口直接返回原 `aiComment`、原 `source` 和 `reused: true`，不调用模型、不重写历史，也不人为补上 mock 标识。用户没有习惯时，鼓励接口仍返回 `{ "cheer": null, "source": null }`，不含 `execution`。

前端通过 `SourceBadge` 显示“模拟结果 · 未连接云端”，并把模拟短评保存在独立预览状态中。不得把 `preview` 塞进已保存的笔记、日记、自习、信箱或理解列表。

## 3. 自习运行状态与确认保存

| 方法与路径 | 请求 | 成功响应 |
| --- | --- | --- |
| `GET /study/active` | 无 | 本人的运行状态，或 `null` |
| `POST /study/active` | `plannedMinutes: 1–240` 整数，可选 `subject` 最长 20 字符 | 新的 `running` 运行状态 |
| `POST /study/active/:id/finish` | 无需客户端实际时长 | `finished` 状态与冻结时长；重复请求复用结果 |
| `DELETE /study/active/:id` | 无 | `{ "cancelled": true }` |
| `POST /study/sessions` | `{ "runId": "...", "note": "..." }`，收获最多 200 字符 | 写入数据库后的自习记录 |

运行状态含 `id`、`status: running|finished|saved`、`subject`、`plannedMinutes`、`startedAt`、`finishedAt`、`actualMinutes`、`savedSession`、`serverNow`。未结束时 `finishedAt/actualMinutes` 为 `null`，未保存时 `savedSession` 为 `null`。

运行状态的 `execution` 为 `{ mode: "mock", storage: "memory", persisted: false, expiresAt: ISO时间 }`。此处 `persisted: false` 指临时运行状态；`savedSession` 若非空，它对应的学习记录已经写入数据库。

开始与结束时间由服务器产生。前端利用 `serverNow` 校准显示时钟，每秒只刷新界面，不逐秒请求 API。结束时按下式冻结时长，之后的重试不会重新累计：

```text
actualMinutes = min(plannedMinutes, max(1, ceil((finishedAt - startedAt) / 60000)))
```

因此不足一分钟记为一分钟，超过计划时长则截到计划时长。提交 `runId` 时，服务端采用该运行状态中的科目、计划时长、实际时长和开始时间，忽略客户端伪造的同名字段。保存失败保留 `finished` 草稿；同一轮次的并发确认或重试共享保存结果。保存中不能取消，返回 409。

这只是有限的接口预览实现：

- 每个用户最多一轮，整个进程最多 1000 个用户；无后台清理线程，访问时移除到期状态。
- 状态从开始起 24 小时过期，服务进程重启后丢失；不支持多实例共享或跨重启恢复。
- 未保存的旧轮次需要先完成并保存或取消，否则新建返回 409；已保存轮次允许被下一轮替换。
- 不存在、已过期或不属于本人的运行 ID 返回 404；容量已满返回 503。
- 删除临时运行状态不删除已保存的学习记录。去重仅在该轮次仍存在时有效，不是持久化幂等键。

既有手动补录仍受支持：不提供 `runId`，提供 `actualMinutes`（1–240），可选 `plannedMinutes/subject/note/startedAt`。省略计划时长则等于实际时长，省略开始时间则使用服务器当前时间。**手动补录由调用方申报时长，每次成功请求创建一条记录；服务端计时权威仅适用于新 `runId` 确认路径。**

## 4. 经期记录与服务端推算

`GET /tools/period/summary?today=YYYY-MM-DD` 读取本人的最新开始记录。可选 `today` 用于客户端所在时区的日历日；不传则取服务器本地今日。

```json
{
  "asOf": "2026-09-12",
  "nextDate": "2026-09-28",
  "daysUntil": 16,
  "basedOnRecordId": "示例记录ID",
  "source": "server_calculation"
}
```

这里只做“最新开始日期 + 该条记录的 `cycleDays`”计算；`daysUntil` 不小于 0。没有记录时 `nextDate/daysUntil/basedOnRecordId` 均为 `null`。该结果不是云端分析，也不表示医学判断。

`PUT /tools/period/:id` 接受部分 `startDate/endDate/cycleDays`；省略字段保留原值，`endDate: null` 清空结束日期。结束日期不得早于开始日期，周期必须为 20–45 的整数。日期按 UTC 零点保存。创建记录时未传周期默认 28。删除接口只删除本人指定记录；编辑／删除后重新获取 summary，避免保留过期推算。

## 5. 美颜与衣柜 multipart 预览

两条接口使用 `multipart/form-data`，单个文件字段名都为 `image`。文件只在服务端内存中接收，大小上限 **8 MiB（8 × 1024 × 1024 字节）**，支持 PNG、JPEG、WebP。服务端核对文件签名与声明 MIME，但尚未执行完整图片解码，不能把校验通过解释为成功生成。

| 接口 | 唯一允许的文本字段 | 返回的结果 |
| --- | --- | --- |
| `POST /work/media/makeup/preview` | 必填 `params`：JSON 字符串，恰好包含 `smooth/whiten/slim/eye` 四个 0–100 整数 | `result.kind: image`、`imageUrl: null`、原参数与说明 |
| `POST /work/media/wardrobe/preview` | 可选 `name`：去掉首尾空白后最多 30 字符 | `result.kind: model`、`modelUrl: null`、单品名与说明 |

请求最多一个文件、一个文本字段，文本字段最多 1024 字节；不接受远程图片 URL、多文件或额外字段。上传／参数不合法返回 400，文件过大返回 413；响应带 `Cache-Control: no-store`。美颜结果不会生成或保存图片，衣柜结果不会生成 3D 模型或把单品加入衣柜。

示例（只展示表单内容，不包含真实用户照片）：

```text
image: <本机选取的图片文件>
params: {"smooth":30,"whiten":20,"slim":0,"eye":0}
```

## 6. 工作会话与定时任务的暂停边界

工作会话使用已保存会话的 `mode`，不信任客户端另传的模式。普通工作消息在模型调用、工具执行和本轮消息落库前被拒绝：

- `POST /chat/conversations/:id/messages`：HTTP **503**，错误码 `WORK_CLOUD_NOT_CONNECTED`。
- `POST /chat/conversations/:id/messages/stream`：请求校验成功后已经写出 HTTP **200 SSE**，随后发出 `data: {"event":"error","code":"WORK_CLOUD_NOT_CONNECTED"}\n\n` 并结束。客户端必须读取事件中的错误码，不能只检查 HTTP 状态。

既有危机检测优先于工作云端门，仍可产生原来的阻断结果／事件；普通聊天模式不属于本轮工作生成 mock 的范围。

`POST /memories/suggestions` 接受 `messageId`，先核对本人用户消息及其会话归属。从工作会话的普通历史消息请求记忆候选时，提取前返回 HTTP 503／`WORK_CLOUD_NOT_CONNECTED`；危机消息继续返回空 `candidates`。工作模式前端隐藏该建议入口，避免从历史消息绕行到真实提取；普通聊天的记忆候选保持既有行为。

工作模式输入栏不提供语音输入，也不探测 ASR 状态。从普通聊天切换到工作模式时，正在申请的麦克风、录音片段、转换和转写结果均被作废；已有转写请求会尝试中止，迟到结果不写入输入框。普通聊天的 ASR 接口与正常语音能力保留，此改动不是停用整站 ASR 服务。

自定义提醒的 CRUD 继续保存个人设置。用户可通过 `PUT /reminders/scheduled/:id` 设置 `status: paused|active`，编辑内容、时间、频率及可选任务指令。指令最多 500 字符；有指令的计划能保存，不代表执行器已接通。

`GET /reminders/due` 会为到期 active 提醒创建或复用 pending 投递行，因此它并非完全无数据库写入。对 `instruction` 非空、`result === null` 的投递，本轮行为是：

1. 从返回的 `deliveries` 中排除，并在 `deferredTaskCount` 中报告数量。
2. 不领取执行、不调用 agent／模型、不写入任务产出、不推进该任务的 `nextFireAt`。
3. 普通纯提醒及已有结果的待确认投递仍可返回给前端。

`POST /reminders/deliveries/:id/ack` 接受 `action: shown|dismissed`。对 pending 且有指令、尚无结果的任务，以及 running 中的任务，返回 409；不能通过直接调用确认接口跳过执行并推进调度。事务中的条件更新和结果复查也保留此约束。纯提醒或已有结果的投递继续按原确认流程处理。

此处 `execution.persisted: false` 仍指模拟生成结果，不意味着到期投递行没有被创建。当前为前台轮询，不包含后台 worker 或系统推送承诺。

## 7. 对接与核对依据

所有上述 API 在 `apps/api/src/app.js` 下使用 `authMiddleware`，要求 `Authorization: Bearer <access token>`。缺失、无效或过期 token 返回 401。对象读写按当前用户归属校验，跨用户对象按不存在处理。通用错误以 `error` 字符串返回，部分入口附 `code` 或校验 `details`；不能假定所有错误都有统一业务码。

源码核对入口：

- `apps/api/src/routes/work.js`、`services/workCloudService.js`：固定状态与文字模拟接口。
- `routes/study.js`、`services/studyService.js`：运行状态、确认保存、手动补录和短评。
- `routes/tools.js`、`services/toolService.js`：日程与经期记录及日期推算。
- `routes/workMedia.js`、`services/workMediaService.js`：上传约束与媒体模拟响应。
- `routes/diary.js`、`habits.js`、`reading.js` 与同名 services：个人记录及模拟短评。
- `services/derivedService.js`、`letterService.js`：仅预览的新分析与来信。
- `routes/chat.js`、`services/chatService.js`：普通请求与流式错误差异。
- `routes/memories.js`、`services/memorySuggestionService.js`：工作会话历史消息的记忆提取边界。
- `apps/web/src/components/chat/InputBar.jsx`、`useVoiceInput.js`：工作模式禁用语音及切换时丢弃录音／转写。
- `routes/reminders.js`、`services/reminderService.js`：提醒持久化与未执行任务。

文档自检范围：JSON 可解析、OpenAPI 3.0.3 必要结构、内部 schema 引用可解析、路径／HTTP 方法与路由源码一致。业务验证使用各服务及页面的专项测试；接口文档检查不替代真实云端接入、图片解码、浏览器视觉或用户验收。

## 8. 本轮审查与验证

从数据归属、模拟结果隔离、异步失败、隐式模型调用、日期语义和浏览器交互分别审查，并修复了以下问题：

- 尚未执行的任务可以被直接确认并推进日程：增加 409 校验及事务条件约束。
- 历史工作消息可以经记忆建议入口触发模型：按消息所属会话模式拒绝，并隐藏工作模式入口。
- 共享语音输入可能沿用真实转写：工作模式停用，切换时取消录音与请求并丢弃迟到结果。
