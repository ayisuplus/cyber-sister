## 零、先建立正确的心智模型

在碰代码之前，请先接受三件事——它们会解释这个项目里很多"看起来奇怪"的设计：

**1. 先区分产品身份与分发能力。**

Amie 保留 AI 姐妹身份，不做虚拟恋人与心理咨询。2026-09-16 起只有一种对话：网页版开放对话、「她」和设置；本地分发另有生活功能及受开关约束的工具执行。当前入口与未决边界见[项目现状与整理记录](../architecture/project-review-20260917.md)。

**2. 文档比代码更需要维护，但文档经常是错的。**

这个仓库有大量文档，但其中不少是**历史归档方案**（微服务、K8s、Redis、向量库等），写得详实但**不代表当前实现**。读到任何架构文档，先看顶部有没有"历史/未来方案归档"警告。

**3. "没做完"必须诚实标注。**

生图没接好就显示"接入中"，天气没数据就 409 关闭，会员没支付就明说。这是我们产品的一部分，不是需要掩盖的缺陷。

## 一、第一天：跑起来

### 目标

能在本地登录，发出第一条消息。

### 步骤

1. **读三份文档**（约 40 分钟）
   - [`README.md`](../../README.md) — 内测范围、仓库结构、完整启动命令
   - [`docs/Spec_Amie_v1.0.md`](../Spec_Amie_v1.0.md) — **实施基线合同**，最重要
   - [`CONTRIBUTING.md`](../../CONTRIBUTING.md) — 环境搭建与提交规范

2. **搭环境**（约 1 小时，按 CONTRIBUTING 步骤）
   - Node.js 24 / pnpm 11.5.1 / Docker
   - `pnpm install --frozen-lockfile`
   - `docker compose -f compose.dev.yaml up -d`
   - 配置 `../.local-secrets/` 下的密钥文件

3. **跑起来并登录**
   - 启动 API 与 Web
   - 用白名单手机号 + 固定验证码登录

4. **预期会遇到的"不是 bug"**
   - 未配置云端供应商 → 聊天返回 `LLM_UNAVAILABLE`
   - 装扮当前只提供模拟预览；旧 MediaPipe 运行描述不代表当前页面
   - 天气不可用（内测 409）

> 第一天跑不起来很正常，环境问题卡住直接问，别自己耗。

### 自检

- [ ] 能登录并看到聊天界面
- [ ] 配置模型且同意授权后，能得到真实回复；`LLM_UNAVAILABLE` 只说明缺配置，不能算聊天验收通过
- [ ] 能打开「她」；本地分发下能看到安排、手记、经期和装扮入口
- [ ] 知道去哪里提 Issue

### 2.4 理解核心链路

**聊天链路**（最重要，先搞懂这条）：

```
用户输入
  ↓
危机检测（最先！命中则阻断，模型调用为零）
  ↓
同意状态检查（未同意禁止调用云端；每次外发前重查）
  ↓
agentTurn 统一回合 → llmService → llm-gateway 云端调用（本地分发可按需执行工具）
  ↓
输出安全过滤（命中红线替换为安全模板）
  ↓
持久化用户消息 + AI 消息
```

**关键约束**（背下来）：

- 危机检测**先于**模型调用，命中时**模型调用次数为零**
- 模型输入按 Spec 的同意与消息合同裁剪、**脱敏**；工具反馈与附件有独立限额
- 日志**不含**聊天正文、记忆、凭据、图片
- 模型失败 → 该次消息**不持久化**，前端保留输入

- [ ] 参与过至少一次 Code Review（作为 reviewer）
- [ ] 独立负责并完成一个 P1 需求

### 3.2 常见踩坑

| 坑 | 现象 | 解决 |
|----|------|------|
| **Windows EPERM** | 跑 `pnpm test` 报 Prisma 引擎文件占用 | 先停掉 dev API（`node --watch` 占用文件） |
| **装扮没有生成结果** | 返回 `cloud_mock`、原图不变 | 当前只有模拟预览；不能把滑杆变化或构建成功当作真实生成 |
| **Docker 拉不动** | Docker Hub 不可达 | 用镜像代理拉取后打标签（命令见 README） |
| **误信归档文档** | 按微服务方案实施 | 检查文档顶部警告，以 Spec 为准 |
| **数据库改错** | 用了 `db push` | 只用 `prisma migrate deploy`，`db push` 被明令禁止 |
| **日志泄漏** | 调试时打了聊天正文 | 上线前必须清理，违反 Spec §8 |

## 四、项目特有的红线（再次强调）

| 红线 | 违反后果 |
|------|----------|
| AI 身份不可被人格或用户提示覆盖 | 合规风险 |
| 危机检测必须最先，命中时模型调用为零 | **阻塞发布** |
| 未书面批准的危机文案不得进仓库 | **阻塞发布** |
| 图片上传须明确用途；装扮模拟预览会送到应用后端，旧文档冲突见 R8，不据此扩展外发范围 | 隐私风险 |
| 送模型的数据必须脱敏，并符合场景限额与授权范围 | 隐私风险 |
| 日志不记聊天正文、记忆、凭据、图片 | 隐私风险 |
| 密钥、白名单不进仓库 | 安全事故 |
| 数据库只用 `migrate deploy` | 数据事故 |
| 不弱化安全红线、不引入情感诱导付费 | 合规风险 |

详细规则见 [`06-合规/内容审核策略.md`](../06-合规/内容审核策略.md)。
