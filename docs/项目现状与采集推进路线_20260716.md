# Amie项目现状与采集推进路线

**盘点日期：2026-07-16**  
**判断原则：以当前文件、数据审计和可运行代码为准，不沿用历史口头统计。**

## 结论先行

项目已经具备可用的前后端 MVP、基础 QLoRA 训练骨架和规模可观的公开评论语料；但当前最紧急的工作不是继续追求“更多评论”，而是把数据从“平台文本集合”重构为“可安全训练的情感陪伴对话集”。

当前 `sft_training_data.jsonl` 的 20,696 条记录中，18,991 条来自小红书评论。它们大多是把随机合成的用户情绪提示与原始评论直接配对，评论并不必然是对该用户的回应。若直接训练，模型将学习到答非所问、无上下文短评、营销表达和不安全建议，不能作为Amie主 SFT 集。

因此建议立即停止把新增普通评论直接混入主 SFT；采集可以继续，但应切换为“真实楼中楼回复链 + 高质量情感求助场景 + 可验证上下文”的定向采集。

## 当前资产盘点

### 产品与工程

- `Agent/` 已有 Express + Prisma + React/Vite MVP，包含认证、会话、消息、记忆、工具和合规路由。
- 数据库处于 SQLite 开发态，`Agent/server/src/prisma/schema.prisma` 已定义用户、会话、消息、记忆、待办、经期和危机日志等实体。
- 当前对话仍使用 `Agent/server/src/services/llmService.js` 的固定回复库；`Agent/server/src/routes/chat.js` 尚未接入真实模型、SSE 流式输出、记忆检索或危机响应 SOP。
- QLoRA 训练骨架已修复 assistant-only loss、4-bit 准备和统一聊天模板；编码单元测试 4/4 通过。

### 训练数据（审计结果）

| 项目 | 可解析记录 | 唯一 ID | 关键发现 |
|---|---:|---:|---|
| 笔记 | 2,155 | 2,058 | 至少 97 条重复 ID；美妆 860 条，占 39.9% |
| 评论 | 35,096 | 29,335 | 至少 5,761 条重复 ID；5,257 条缺少 `note_id` |
| 当前 SFT | 20,696 | 17,687 | 至少 3,009 条重复 ID；结构格式全部可解析 |
| SFT 来源 | 18,991 评论 / 1,705 笔记 | - | 91.8% 是评论映射样本，不可直接视为陪伴回复 |

- 当前 SFT assistant 输出中位长度为 30 字；只有 8 条超过 1,024 字符。
- 训练数据文本扫描发现：评论集中至少 1 条疑似手机号，需隔离或脱敏后再进入任何训练集。
- 待处理目录仍保留 6 个已经可读取的历史 Excel 批次，以及 1 个损坏批次 `笔记_20260716_1784175138`。前 6 批需建立“已合入清单”后归档，禁止再次合入；损坏批次需重新导出。

## 核心风险与处理顺序

### P0：冻结数据并建立入库质量门

1. 以当前 `已处理/` 创建不可变快照 `v0`，先去重，再进行字段和来源审计。
2. 建立批次 manifest：记录 Excel 文件哈希、导入日期、笔记数、评论数、是否已合入，彻底阻断重复合入。
3. 执行 PII 脱敏：手机号、微信号、邮箱、身份证样式、@提及、外链和精确地理信息进入隔离队列；未通过扫描的记录不得进入训练集。
4. 将 `待处理/` 重新定义为“入库队列”，已合入文件移动到 `归档/`，只保留损坏或待人工确认的批次。

可复用审计入口：`LLM/scripts/audit_dataset.py`。

### P0：拆分数据用途，停止混训

建立四个互不混用的数据层：

- `canonical/notes.jsonl`：笔记正文与元数据，只作情境、语言和话题分布来源。
- `canonical/comments.jsonl`：评论和可用楼中楼关系，只作用户表达、候选回复和偏好证据来源。
- `training/sft_gold.jsonl`：仅保留“用户表达 -> 真实直接回复”或“人工/模型起草后人工审核的Amie回复”。
- `evaluation/frozen_prompts.jsonl`：固定 300 条场景提示，永不参与训练。

普通评论可用于情绪识别、检索语料、DPO 候选与用户表达库；不应因“点赞高”就被写入 assistant 输出。

### P0：让训练目标与产品对齐

现有 `LLM/scripts/train_lora.py` 能训练 Alpaca 格式的“小红书文案生成”，而产品目标是情感陪伴聊天。当前配置的系统提示也仍是“专业的小红书文案创作者”。

下一次训练前应完成：

1. 让数据构建脚本读取新的对话 SFT，而不是 `data/processed/cleaned.jsonl` 的旧文案数据。
2. 将训练配置的 system prompt 替换为安全版Amie人格规范：有风格，但不羞辱、不诱导依赖、不冒充真人、不提供医疗或危机处置建议。
3. 用 2,000-3,000 条高置信 SFT 跑首个冒烟训练；不要用当前 20,696 条混合样本直接开训。
4. 固定比较“基座模型 / SFT 模型 / SFT+DPO 模型”的盲评结果，而不只看 eval loss。

## 后续采集方向

### 立即停止或降权

- 泛美妆、粉底、护肤：当前已占笔记近四成，只保留少量“容貌焦虑”相关内容。
- 泛 `emo`、泛励志、无上下文短评论：可以进语料池，不再默认进主 SFT。
- 带营销、引流、医疗断言、危机不当建议的文本：直接隔离。

### 第一波：关系边界与自我价值

目标不是泛情绪，而是采集“用户能向闺蜜求助的明确上下文”。每个关键词优先抓取原帖、前 50 条高质量评论、父评论和子评论关系。

| 关键词组 | 业务目的 | 最小目标 |
|---|---|---:|
| `讨好型人格`、`边界感`、`不会拒绝`、`回避型依恋`、`安全感` | 关系模式、设边界、反复拉扯 | 300 个有效上下文 / 1,000 条回复链 |
| `容貌焦虑`、`自我怀疑`、`配得感`、`自卑` | 自我价值与外貌比较 | 300 个有效上下文 / 1,000 条回复链 |
| `职场焦虑`、`职场 PUA`、`被领导骂`、`裸辞`、`失业焦虑` | 高频、可行动的现实困境 | 400 个有效上下文 / 1,500 条回复链 |

### 第二波：家庭与孤独场景

- `原生家庭`、`父母控制`、`家庭矛盾`
- `独居`、`没有朋友`、`孤独`、`社交焦虑`
- `分手后`、`断联`、`冷暴力`、`失恋`

这批要同时构建危机分流标签：普通低落、持续绝望、疑似自伤风险。高风险内容只进入安全评估集，不作为“毒舌闺蜜”回复风格训练样本。

## 数据产品化路线

### 第一阶段：7 天内

- 数据治理：去重、PII 扫描、批次 manifest、归档清理。
- 对话构造：保留带父子关系的真实回复链；选 500 条人工快速审查。
- 评估集：完成 300 条冻结 Prompt，覆盖焦虑、关系冲突、职场、自我价值、孤独和危机边界。
- 工程：为 LLM 调用定义稳定接口，先接基础模型；危机输入返回正式安全响应而非空 `aiMessage`。

验收：可获得一份无重复、无已知 PII、可追溯的 2,000-3,000 条高置信陪伴 SFT 候选集。

### 第二阶段：2-3 周

- 完成首轮 QLoRA 冒烟训练和基座对比盲评。
- 基于真实回复链和人工改写构建首批 500-1,000 对 DPO 数据。
- 实现基础模型推理服务、SSE、会话上下文拼接、规则型危机分流和审计日志。
- 记忆系统先做“瞬时上下文 + 用户确认的显式记忆”，不急于上 Neo4j/Milvus 全栈。

验收：模型在冻结评测中相对基座，闺蜜感、上下文相关性与安全合规均有可量化提升；危机样本 100% 进入安全路径。

### 第三阶段：4-6 周

- 扩展高质量 SFT 至 8,000-12,000 条，DPO 至 3,000 对以上。
- 完成真实模型接入、基础记忆、合规后置检查、监控和灰度评估。
- 再考虑 PostgreSQL、Redis、向量检索和 vLLM 多模型路由；这些应服务于已被评估证明有效的聊天闭环。

## 最终决策建议

下一批搜索应从 **“讨好型人格 + 边界感”** 开始，并同时保留完整楼中楼关系。它比继续搜泛 `emo` 更能补足当前“原生家庭仅 2 条、自我价值仅 1 条、焦虑仅 49 条”的结构性缺口，也更贴近Amie需要处理的真实对话。

但采集之前先完成数据治理。否则每新增 1 万条评论，训练集的重复、错配和风格漂移也会同比扩大。
