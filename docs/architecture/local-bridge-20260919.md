# 本机助手：让 Web 版的她伸到你的电脑里

状态：✅ 当前有效（2026-09-19 首版；本地测试与真实 HTTP 往返通过，未在部署主机上验收）

## 为什么

产品负责人 2026-09-19 拍板：只做一个 Web 版，但不能让智能体「完全伸不到用户电脑里」。托管服务器只有 2 核 2G，也不该替用户跑代码、开浏览器；服务器也连不进用户家里的电脑。所以由用户电脑上一个很小的程序**主动外连**到 Amie：它来取任务，在本机执行，把结果交回。电脑上不开任何端口。

这对应《人类—AI 双原生知识系统构想》里的「人在场授权，Agent 就是人的手」：用户自己打开助手、自己指定文件夹，助手关掉就断开。

## 结构

```text
浏览器（设置页）──生成连接码──▶ Amie API ◀──长轮询取任务 / 交回结果── 本机助手（用户电脑）
                                   │                                   │
               聊天里她调用工具 ──▶ 任务中转（进程内存）              只在授权文件夹里执行
```

| 部分 | 位置 | 责任 |
| --- | --- | --- |
| 配对与身份 | `apps/api/src/services/bridgeService.js`、表 `local_bridges` | 一次性 8 位连接码（10 分钟、只能用一次、条件更新领取）换长期令牌；两者只存 SHA-256；每人最多 3 台；断开即清令牌 |
| 任务中转 | `apps/api/src/services/bridgeBroker.js` | 每台电脑一个 25 秒长轮询；任务交给最近在线的那台；超时 60 秒、调用方取消、断开时在途任务失败；只接受发给这台电脑的结果 |
| 路由 | `apps/api/src/routes/bridge.js` | 设置页（登录）：`POST /api/bridge/pairings`、`GET /api/bridge`、`DELETE /api/bridge/:id`；助手：`POST /api/bridge/claim`（连接码）、`GET /api/bridge/poll`、`POST /api/bridge/jobs/:id/result`（`Authorization: Bridge <令牌>`） |
| 她的工具 | `apps/api/src/services/bridgeTools.js` | `list_local_files`、`read_local_file`（每次 2 万字，可续读）、`write_local_file`（只新建）。只有助手在线时才进入这一轮的工具目录 |
| 本机助手 | `apps/bridge`（Node 24，零依赖） | 配对、长轮询、在授权文件夹里执行；终端里逐条写出她做了什么 |
| 设置页 | `apps/web/src/components/profile/LocalBridgeSettings.jsx` | 生成连接码与命令、已连接的电脑与在线状态、断开 |

## 边界

- **授权文件夹是唯一范围**，由助手在本机做权威校验：只接受相对路径；`..`、绝对路径、盘符、指向外面的链接一律拒绝；新文件检查最近一级已存在父目录的真实位置，建完父目录再核对一次。
- **只看、只读、只新建**：不覆盖（`wx` 打开）、不删除、不运行任何东西；读文件限 2MB 且拒绝二进制；写入限 1MB。
- **读到的内容会交给云端模型**：设置页与助手启动时都明说；文件里的文字按资料处理，不当作用户的新指令（写在她的工具提示里）。
- 令牌保存在用户目录 `.amie-bridge.json`（尽量设为仅本人可读）；服务端只存哈希。
- 取任务与交结果不占用户普通请求额度（同一家庭网络常共用公网 IP），另按令牌计 600 次 / 15 分钟。
- 助手离线时，她的工具目录里没有这些能力，调用也如实回复「没有连接你的电脑」。

## 怎么用（内测）

还没有安装包。电脑上需要 Node.js 24：

```bash
# 在 Amie「设置 → 连接你的电脑」生成连接码，然后：
node apps/bridge/src/cli.js pair ABCD2345 --server https://你的 Amie 网址 --folder "D:\想让她看的文件夹"
# 以后再打开：
node apps/bridge/src/cli.js run            # 换文件夹：run --folder <新文件夹>
```

`--server` 只接受 https（本机调试可用 `http://localhost`）。

## 验证

- API：任务中转 8 项、配对与身份 8 项、路由 4 项、工具 4 项；真实 HTTP 往返 1 项（仓库里的助手客户端连本机起的服务，列目录、读、新建、拒绝覆盖与越界）。
- 助手：10 项（越界、符号链接、分段读、二进制、不覆盖、客户端重连与令牌失效）。
- 真实 PostgreSQL 2 项（并发领取只成功一次、过期码、断开后令牌失效），本机无数据库未运行，交给 CI。
- Web：设置卡片 4 项；Playwright 64 项。

## 还没做

- 安装包（Windows/macOS 双击即用）与开机自启。
- 把现有「本机能力」（隔离 Python、独立浏览器、生图、后台任务）也改走助手；目前它们仍只在 API 本身跑在用户电脑上（`APP_DISTRIBUTION=local`）时开放。
- 覆盖、删除等写操作需要逐次确认的界面；在那之前一律不支持。
- 任务中转在进程内存里，只适合当前单实例部署；多实例需要共享队列。
