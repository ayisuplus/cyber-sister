## 必须解决的 P1

### F1：同一违规人设反复提交可以通过校验

位置：[personaStudio.js:64](../../apps/api/src/services/personaStudio.js#L64)、[personaStudio.js:78](../../apps/api/src/services/personaStudio.js#L78)。

模块级 `VULGAR_PATTERNS` 含全局 `/g` 正则，而 `.test()` 会保留 `lastIndex`。用同一张合成人设卡连续调用四次校验，结果为 `rejected, accepted, rejected, accepted`。保存与蒸馏复用此校验，故不是单纯 UI 问题。

验收：同一非法输入重复、交错及并发请求始终拒绝；合法输入不受上一请求影响。采用无状态匹配即可，无须新增校验框架。

### F2：人设提炼绕过已有敏感文本脱敏

位置：[personaStudio.js:336](../../apps/api/src/services/personaStudio.js#L336)、[personaStudio.js:395](../../apps/api/src/services/personaStudio.js#L395)。

提炼直接调用 `gateway.complete`，将原始素材拼入 `promptText`，没有经过 `redactSensitiveText`。用模拟网关捕获请求，合成手机号与邮箱均完整存在于 `messages`；未发送真实网络请求。这与 PR 安全清单“送入模型的数据已脱敏”不符。

同样需核查保存的人设卡作为 `personaBody` 进入系统提示的路径：网关目前直接拼接该文本，未集中脱敏。

验收：素材、调研文本与人设提示的发送副本去除直接标识符；保留用户原始存储内容；发送前重新检查同意，拒绝/撤回时调用为零。

### F3：默认升级只建人设表，旧用户的说话方式没有迁移

位置：[migration.sql:2](../../apps/api/src/prisma/migrations/20260929120000_personas/migration.sql#L2)、[migrateDeploy.js:15](../../apps/api/src/prisma/migrateDeploy.js#L15)、[start-local.mjs](../../scripts/start-local.mjs)。

SQL 明确将枚举转人设卡交给单独的 `db:migrate:personas`，但正常迁移入口、一键启动和现有发行流程均未串接它。已有用户登录也直接返回原用户，不补建卡。

真实 PostgreSQL 合成旧用户原为 `toxic`。仅执行默认迁移后：人设列表为空、上下文回落 `gentle`；额外手工执行数据迁移后：恢复 1 张卡与 `toxic` 底色。这证明数据库 ready 不等于升级正确。

验收：升级自动执行幂等回填，失败阻止进入可用状态；六种旧枚举、未知值、重复升级与回滚都有明确结果。先备份，先在合成旧库验证。

### F4：并发删除能删空人设并留下失效的当前指针

位置：[personaStudio.js:259](../../apps/api/src/services/personaStudio.js#L259)。

“至少一个”的数量与候选查询在事务外完成。两个请求同时读到两张卡后，各自可以删掉一张；事务内选出的替代项也来自旧快照。

在真实 PostgreSQL 上用同步屏障固定这个交错，两个删除请求均成功，最终 `remaining=0, activeExists=false`。这会违反“至少留一个她”，并使当前人设静默回落默认值。

验收：同一用户的删除/切换在事务内使用同一并发保护并重读剩余项；并发删除至多成功一个，当前指针必须指向该用户仍存在的卡。

### F5：深度沉浸明确关闭“冒充真人”红线

位置：[llmService.js:555](../../apps/api/src/services/llmService.js#L555)、[llmService.js:662](../../apps/api/src/services/llmService.js#L662)、[personas.js:19](../../packages/llm-gateway/src/personas.js#L19)。

`immersion=high` 时 JSON、SSE 与最终输出都传入 `identityClaims=false`。合成输出“我是真人，不是 AI。”在普通模式被过滤，在该模式直接通过。提示词同时要求“不提 AI 身份”，UI 描述为“连身份也不出戏”。

这是与当前 Spec §4、PR 红线清单及用户提供的“未弱化红线”约定的直接冲突。源码注释称 09-29 已裁定，但当前基线与路线图没有同步记录；本审查不把注释当成新的产品批准。

验收：任何档位保留身份安全边界，或先由产品负责人书面裁定角色内表达与真实身份询问的边界，再同步基线和冻结验收集。不能只删断言让测试变绿。

### F6：冻结危机用例的已知失败仍被算入绿色测试

位置：[spokenInput.test.js:57](../../apps/api/tests/spoken-input/spokenInput.test.js#L57)、[detection.js:161](../../apps/api/src/services/detection.js#L161)、[spoken.cases.json](../../apps/api/tests/spoken-input/spoken.cases.json)。

套件用 `it.fails` 记录缺口。包括高风险语音变体“我真的不想，嗯，活了。”与同音误写“我真的不像活了。”；直接运行检测，两者均返回 `null`，冻结期望为 `high`。前者不仅涉及识别错误，也包含口头语和标点。

此处如实登记缺口是优点，但不能满足合规清单 1.7“冻结输入集全部通过”。这是已有缺口，不是本轮新增人设导致的回归。

验收：至少修复已确认的高风险口语漏检，并用真实录音确认同音情形；保留引用、否定、第三人称等避免误报的反例。未修项目必须进入正式门禁结果，不能仅用预期失败代表验收完成。

### F7：核心浏览器验收仍有 15 项失败

位置：[local-features.spec.js:47](../../apps/web/e2e/local-features.spec.js#L47)、[night-mode.spec.js](../../apps/web/e2e/night-mode.spec.js)、[openers.spec.js:74](../../apps/web/e2e/openers.spec.js#L74)。

多项失败报 `Unmocked API request: /api/user/personas`，说明夹具未适配新增接口。桌面和手机均受影响，实际执行结果为 71 通过、15 失败。修复复验确认：补齐该接口后开场区原有来源文案断言通过，无须改文案或放宽断言。

这是明确的 CI / 发布门禁失败；不能据此断言所有对应功能在真实后端均损坏，也不能把单测通过替代浏览器结果。

验收：夹具对应真实人设数据与当前交互，新增人设创建/修改/切换/删除覆盖；原有记忆、生活入口、夜间、320px 与开场区恢复通过，随后跑一次真实 API 的核心路径。

### F8：本地默认 PostgreSQL 端口绑定全部宿主接口

位置：[compose.dev.yaml:15](../../compose.dev.yaml#L15)、[start-local.mjs](../../scripts/start-local.mjs)。

一键启动使用的开发 Compose 写的是 `"5432:5432"`，搭配公开测试口令。本次读取已有容器的端口映射，确认为 `0.0.0.0:5432` 和 `[::]:5432`；没有更改该容器。

实际外部连通性仍取决于防火墙，但默认配置并未提供回环隔离。文件注释的“禁止共享部署”也没有阻止一键启动暴露该端口。

验收：本机默认只发布到回环地址；自部署使用单独的非公开凭据与网络配置。确认 IPv4、IPv6 绑定及启动文档一致。
