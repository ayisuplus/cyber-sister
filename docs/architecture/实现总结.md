## 三、使用指南

### 3.1 开发环境

**1. 安装依赖**：
```bash
# 后端
cd server
npm install

# 前端
cd ../client
npm install
```

**2. 初始化数据库**：
```bash
cd server

# 生成Prisma客户端
npm run db:generate

# 推送数据库schema
npm run db:push

# 初始化测试数据
npm run db:seed
```

**3. 启动开发服务器**：
```bash
# 终端1：启动后端
cd server
npm run dev

# 终端2：启动前端
cd ../client
npm run dev
```

**4. 访问应用**：
- 前端：http://localhost:5173
- 后端API：http://localhost:3000
- 健康检查：http://localhost:3000/api/health

### 3.2 Docker部署

**1. 配置环境变量**：
```bash
# 复制环境变量示例
cp .env.example .env

# 编辑.env文件
JWT_SECRET=your-super-secret-jwt-key
JWT_REFRESH_SECRET=your-super-secret-refresh-key
```

**2. 启动服务**：
```bash
# 构建并启动
docker-compose up -d

# 查看日志
docker-compose logs -f

# 停止服务
docker-compose down
```

**3. 访问应用**：
- 前端：http://localhost
- 后端API：http://localhost/api
- 健康检查：http://localhost/health

### 3.3 数据库管理

**查看数据库**：
```bash
cd server
npm run db:studio
```

**重置数据库**：
```bash
cd server
npm run db:push --force-reset

```

## 五、关键改进总结

### 5.1 数据持久化

**之前**：
- 所有数据存储在内存Map中
- 服务重启即丢失所有数据
- 无法支持多实例部署

**之后**：
- 所有数据存储到SQLite数据库
- 数据持久化，服务重启不丢失
- 支持多实例部署（使用PostgreSQL）

### 5.2 安全加固

**之前**：
- JWT密钥硬编码在代码中
- Mock Token后门
- 无输入验证
- CORS完全开放

**之后**：
- JWT密钥从环境变量读取
- 移除Mock Token后门
- 所有API添加输入验证
- CORS配置限制

### 5.3 代码质量

**之前**：
- 无结构化日志
- 错误处理简单
- 前后端Mock逻辑重复
- 前端状态不持久化

**之后**：
- 结构化日志服务
- 统一错误处理
- 前端统一调用后端API
- 前端状态持久化

### 5.4 部署能力

**之前**：
- 无Docker配置
- 无Nginx配置
- 手动启动服务

**之后**：
- Docker容器化部署
- Nginx反向代理
- 一键启动服务

## 八、总结

本次实现完成了从MVP原型到生产就绪的完整升级，主要改进包括：

1. **数据持久化**：使用Prisma ORM，所有数据存储到数据库
2. **安全加固**：移除Mock Token后门，JWT密钥从环境变量读取
3. **输入验证**：所有API添加参数验证，防止恶意输入
4. **错误处理**：统一错误处理和结构化日志
5. **状态持久化**：前端Zustand Store添加persist中间件
6. **容器化部署**：Docker一键部署，Nginx反向代理

这些改进为后续的功能开发和系统扩展奠定了坚实的基础。
