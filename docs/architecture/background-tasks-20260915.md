# 工作模式后台任务

状态：✅ 当前有效。更新于 2026-09-15。当前用于本地调试，尚未部署 VPS。

## 使用与生命周期

工作输入栏选择「后台执行」后提交，服务器返回 202 和任务 ID。任务及上传内容存入 PostgreSQL，离开页面或退出登录不会撤销已经提交的任务。重新进入工作模式可查看最近 20 项任务的状态、计划及结果；「取消任务」才发出取消请求。普通聊天和原 SSE 发送仍在断线时取消。

状态为 `queued → running → completed / failed / cancelled`；未知版本的检查点或无法确认的在途写操作进入 `paused`，不会自动重放。失败任务可显式从保存步骤继续；取消清除暂存输入和检查点，已有完整会话结果不被删除。

同一用户只能有一个排队、运行或待核对任务，由数据库部分唯一索引约束；每个 API 进程最多同时处理两个任务。每次启动最多运行 15 分钟，最多自动启动三次（包括首次）；失败后的用户显式重试重置启动次数，保留已完成的工具步骤。

## 持久化与隔离

`WorkTask` 关联用户和会话，删除用户或会话会级联清理任务。提交的 `Idempotency-Key` 按用户唯一，正文与上传字节的摘要用于识别冲突；同键同内容返回原任务，同键不同内容返回 409。请求标识不能授权跨用户查询。

每次工具执行前先保存检查点，完成后保存真实工具结果、去重缓存、历史和暂存文件。恢复保留文件 ID 和已完成步骤；中断的读取或沙箱计算可能从该步骤重新运行。后台工具目录限定为读文件、公开网页/搜索、匿名网页操作、查看日程、计算、计划和生成文件；增删改用户记录不进入后台目录，旧文本工具协议也无法绕过执行层限制。浏览器操作不复用去重缓存，重启后需重新打开页面，详见[网页操作](work-browser-20260915.md)。

工作进程使用 30 秒租约，每 10 秒续租。领取、取消和最终提交采用一致的锁顺序；模型每次调用、工具执行和结果提交都会校验当前租约与取消状态。过期执行者不能覆盖新租约或写入迟到结果。正常停机中止在途调用并重新排队；硬重启后等待过期租约再恢复。

最终状态、用户/助手消息、上传/生成文件与角色经历在同一事务提交，避免「任务已完成但没有文件」或重复成长。尚未成功的检查点不成为正式记忆。个人导出包含任务正文、状态和尚未提交的上传内容，不包含租约令牌、幂等标识和模型检查点；导入该记录不自动执行任务。

任务列表和进度接口返回状态及工具摘要，不返回暂存文件正文、完整模型历史或执行令牌。轮询经过鉴权，与记忆索引进度共用每用户每分钟 120 次的独立额度，不消耗普通聊天额度。前端每 5 秒查询一次；旧登录会话或旧页面的响应不会恢复到新会话中。

## 接口与配置

先应用迁移 `20260915140000_work_tasks`，再设置 `WORK_TASKS_ENABLED=true`。Docker Python 另需既有的 `WORK_CODE_ENABLED` 和对应运行镜像；未配置后台执行时，提交返回 `WORK_TASKS_DISABLED`。本地启动脚本已启用。

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| POST | `/api/work/conversations/:id/tasks` | `Idempotency-Key` 请求头，正文 `content`，可附 multipart `files`；返回 202 |
| GET | `/api/work/tasks` | 当前用户最近 20 项任务 |
| GET | `/api/work/tasks/:id` | 当前用户的单项进度 |
| POST | `/api/work/tasks/:id/cancel` | 显式取消；已完成任务返回已完成状态 |
| POST | `/api/work/tasks/:id/retry` | 从失败任务的保存步骤继续；冲突返回 409 |

上传沿用每个 5 MB、最多 3 个、总计 12 MB 的限制；正文最多 10000 字符。后台资料用「添加文件」提交，照片对话仍走原发送入口。

- 内置浏览器检查合成组件的后台选择、提交后清空输入、任务进度、取消反馈和 390 px 内容栏布局；没有替用户登录或接受云端授权。真实接口与视觉组件的证据分别记录。

### 临时执行容器的回收

Python 容器带 `--rm`，由 Docker 在退出后自动删除；API 仍在正常结束和取消时等待强制清理。删除与自动回收竞争时，只有再次查询确认该容器 ID 不存在才算成功；Docker 查询失败不能当作已清理。清理等待期间发生取消也不会返回产物。

Python 容器有专属 `app.amie.sandbox=python-v1` 标签和两分钟的绝对到期时间；浏览器使用 `browser-v1` 标签，普通浏览器四分钟到期，第六批允许确认的浏览器十一分钟到期。启用对应能力的 API 在启动时和每 30 秒检查一次，每批合计最多回收 10 个到期容器，覆盖创建后未启动及运行中失去宿主的情况。没有对应标签、到期值无效或尚未到期的容器不会被回收；启动动作也拒绝休眠恢复后的过期容器。Python 普通执行的 45 秒截止与容器内 30 秒任务超时保持不变。

第四批证据在 `../asset-work/work-agent-runtime-20260915/`：真实 Docker 的 11 项检查通过，覆盖产物字节、选择性回收、强制结束本次测试的 Node 子进程后自动清理和显式取消；所有本次测试容器已移除。API 999 项和 PostgreSQL 47 项全部通过，标准 `test:postgres` 入口也包含后台任务套件。此批未修改 Web，沿用第三批 725 项前端回归。

恢复针对步骤和产物，不恢复 Python 或浏览器容器内存。到期扫描依赖至少一个启用对应能力的 API 在线；API 全部停止期间没有独立的宿主监督器。生产执行隔离与容量压测仍未完成。第五批增加匿名网页操作与截图交付；第六批增加[实际请求确认](work-actions-20260915.md)，需启用 `WORK_BROWSER_WRITES_ENABLED`。用户确认后才提交，结果不确定或提交后的检查点未保存时暂停核对，禁止自动重发。允许确认的浏览器十一分钟到期，普通浏览器仍为四分钟。付费媒体、账号登录和持续的定时/周期任务仍未接通。
