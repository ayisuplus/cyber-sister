# 工作 Agent 与多模态选型

状态：⚠️ 参考（2026-09-17 核对）。本文保留 09-15 的阶段实现与验收证据；09-16 已统一对话并限制本地工具分发，文中的聊天/工作双模式与次数描述不再作为实施依据。当前范围看 [Spec](../../Spec_Amie_v1.0.md)，模块位置与剩余问题看[项目审查](../../architecture/project-review-20260917.md)。

## 当前交付

工作会话使用现有云端模型网关，保留同意检查、危机处理、角色身份、正式记忆和角色成长。日记、学习、装扮等领域的模拟生成状态独立报告，不随工作对话接通而自动启用。

`agentTurn` 共用 JSON/SSE 执行循环：聊天最多 3 次工具调用，工作最多 12 次；连续两次失败或重复调用进入收尾。工作回合向客户端发送开始/完成/失败事件；`update_plan` 以可见步骤表达执行进度，不展示或存储模型内部推理。最终回复保留工具记录及最后计划，重新打开会话仍可查看。

`create_artifact` 支持 Markdown、文本、CSV、JSON、JavaScript、Python、HTML 文件；`list_artifacts` / `read_artifact` 只访问当前用户的当前会话。文件每个最多 200 KB、每轮最多 8 个，长文件分块读取。源码下载不意味着执行或测试通过。HTML 强制附件下载，当前不提供网页预览执行。

第二批补齐文件输入、网页正文、隔离 Python 和 Office/PDF。工作输入栏可上传最多 3 个文件，每个 5 MB、合计 12 MB；支持 UTF-8 文本/CSV、PDF、XLSX、DOCX、PPTX 和 PNG/JPG。文件名、编码、扩展名和二进制签名经过校验。上传文件随用户消息提交，生成文件随助手消息提交，读取历史只返回目录。失败或取消保留输入草稿，不把附件自动写为正式记忆。

`read_artifact` 对 Office/PDF 在隔离容器内提取文字，返回页码/工作表/幻灯片标记和分页偏移。提取上限 120000 字符；PDF/PPTX 最多 100 页，表格最多 30 个工作表、每表 1000 行与 60 列，超限明确返回截断标志。PDF 只读文字层，扫描件 OCR 未实现；表格只读取缓存值，不执行公式。大表的进一步计算使用 `execute_python` 读取原始文件。

`execute_python` 接收明确选择的当前会话文件；每次创建独立 Docker 容器，无网络、无主机目录或 Docker socket 挂载、只读根目录、非 root 用户、禁用新增权限，限制 512 MB 内存、1 CPU、64 进程及 30 秒代码运行时间。输入通过 stdin 传入，输出逐一验证后暂存；失败退出不交付部分文件，取消等待容器删除。支持 pandas、openpyxl、python-docx、python-pptx、ReportLab、matplotlib、pypdf 和中文字体，输出最多 8 个、每个 5 MB、合计 12 MB。本进程最多同时 2 个执行任务、同用户 1 个；目前用于本地调试，生产调度与隔离尚未验收。显式后台任务可以从保存步骤恢复，不恢复容器内存。

环境准备：从仓库根目录执行 `docker build -t amie-work-python:20260915 apps/api/work-runtime`，然后设置 `WORK_CODE_ENABLED=true`。镜像不存在或 Docker 不可用时如实失败，禁止降级到主机 Python。镜像依赖版本固定在 `apps/api/work-runtime/requirements.txt`；本地验收报告记录镜像标识。

`read_web` 读取公开 HTTP/HTTPS 正文：校验 URL、DNS 的全部地址与每一跳重定向，将已验证 IP 固定到连接，阻止本机/内网/保留地址；DNS 等待与网络读取支持取消，连接前再查授权。每页压缩及解压数据均限制 2 MB，正文限制 120000 字符、分块 12000 字符，不执行网页脚本、不携带登录状态。动态页面可使用第五批新增的独立 Chromium：打开、读取控件、点击、公开检索及 PNG 截图，详见[网页操作与验证](work-browser-20260915.md)。真实工具来源单独展示；回答支持 Markdown 表格、代码块和链接，禁用原始 HTML，不自动请求回答里的外部图片。

本地 Dots 已开启 `WORK_NATIVE_TOOLS=true`：由工具注册表提供结构化 function 参数，网关累积原生 `tool_calls`，只在成功收到结束标记后交付给执行层。残缺参数、多调用、截断或后续错误均不能执行；工具参数开始返回后不重试或切换供应商。聊天保持原通道，未启用的工作实例可使用原文本协议。长代码不再在 4 KB 前缀处泄漏到正文，畸形工具 JSON 回馈模型修正。真实验收中的一次纠正保留在工具记录里，不掩盖为全程无误。

Markdown 渲染按需加载，加载时先显示可读文本，来源与文件卡片独立显示。正式构建主包由接入渲染库后的 535668 字节降至 377695 字节，避免登录首屏承担整套文档渲染代码；本项目既有衣橱页面大包警告仍保留。

不可信资料的提示标记不等于完整的提示注入防护。当前经过实测的边界是文件归属、容器无直连网络/无主机挂载、公开地址校验、取消终态和崩溃后的容器回收；浏览器请求通过 API 校验后转发，第六批增加实际请求预览和逐次确认，详见[外部提交确认](work-actions-20260915.md)。临时容器退出时自动删除，API 启动及定期扫描仅回收带专属标签且到期的容器：Python 两分钟，普通浏览器四分钟，允许确认的浏览器十一分钟，详见[后台任务回收](background-tasks-20260915.md#临时执行容器的回收)。账号登录、跨域预检、连接器、付费媒体任务的动作授权与生产隔离仍属于后续工作。

普通 JSON/SSE 回合的文件先保存在内存，模型成功收尾后与两条消息、角色经历同事务提交。取消、供应商错误或文件提交失败均不能留下半轮会话文件。`WorkArtifact` 按用户和会话隔离，删除会话/账户时级联清理；个人数据导出包含文件正文。下载使用认证请求、`attachment`、`nosniff` 和禁用缓存。

第三批实现显式后台任务：提交后保存输入及工具检查点，关闭页面后继续执行；界面恢复进度、取消、失败重试和结果入口。任务完成与消息、文件及角色成长同事务提交，租约阻止旧进程回写；后台目录排除记录写入。已通过真实 Dots 的隔离进程重启验收，详见[后台任务实现与边界](background-tasks-20260915.md)。普通 SSE 断线取消语义保留。

工作文本输出上限 16000 字符；工具消息保留完整协议。上下文最多 48 条、64000 字符，优先保留当前请求与最近反馈。聊天仍沿用原限制。搜索在启用时才进入工具目录；搜索取消传播到 HTTP/CLI，回退前重新检查调用授权。

## 验证与边界

- Dots `dots3-note-prev`：真实模型完成计划、计算 `12+28`、创建 CSV、更新计划 4 次工具操作，SSE 进度、文件下载、会话重新读取、角色成长、跨用户 404 和未同意云端请求均通过。只发送合成数据；生成的测试用户已清理。
- 第二批真实 Dots 验收：上传 CSV 后，约 40 秒内经过一次格式纠正，完成文件读取、计划、公开网页阅读、Python 执行与 Excel/中文 PDF 交付。独立重新解析两份下载文件，验证总计 425、上传字节往返、历史目录、跨用户 404、角色成长及不自动创建正式记忆，16 项检查通过。文本工具通道的三次先前失败与一次本地重启中断保留，不能用成功样本宣称稳定率或旗舰等价。
- Docker 实测：生成并重新解析 DOCX/XLSX/PPTX/PDF 和图表；验证断网、只读根目录、非 root、无宿主凭据及取消回收。生成代码仍需按任务检查结果；容器不是虚拟机隔离，生产执行环境尚未验收。
- PostgreSQL：独立调试实例 `127.0.0.1:55432`，迁移 `20260915120000_work_artifacts` 与 `20260915130000_work_file_inputs`；35 项数据库用例通过，包括上传文件、失败/取消回滚及跨用户隔离。个人数据库与 VPS 未修改。
- 第二批全量回归：API 990 通过，Web 716 通过，网关 20 通过；API 中 35 项 PostgreSQL 用例另行运行并全部通过。内置浏览器查看了合成界面的来源展开、文件卡片、进度与输入栏；该界面检查与真实 API 联调分开记录，没有替用户登录或接受云端同意。lint、typecheck、构建结果见同批验证清单。
- 证据目录：第一批 `../asset-work/work-agent-20260915/`；第二批 `../asset-work/work-agent-io-20260915/`。`live-file-smoke.json`、`runtime-smoke.json` 记录真实执行与文件复核，`verification.json` 汇总最终检查。测试不代表用户已接受界面或开放发布。

## RunningHub 与替代方案

用户在检查 RunningHub 后没有找到合适的现成流程，已于 2026-09-15 改为要求按产品需求自行搭建、优先开源模型。当前已保存 Z-Image Turbo 生图和 Qwen 2511 单张参考图编辑，ID、字段与验证边界见[自建图像工作流](runninghub-workflows-20260915.md)。fal 仍仅作为同规格评测候选，不自动切换供应商。对当前需要妆容、穿搭和角色一致性的产品，自定义流程能力有实际价值。以下比较属于基于文档的工程判断，尚无跨平台成本或效果实测。

| 方案 | 适配场景 | 已确认约束与取舍 |
| --- | --- | --- |
| RunningHub | 自定义 ComfyUI 工作流、封装 AI 应用、多模态模型 | 工作流/应用与直接模型 API 的 Key 权限不同；模型 API 和 LLM API 要求企业级共享 Key。现行任务结果用 V2 查询。国内访问质量、并发、实际费用按账户与目标任务验证。[官方入门](https://www.runninghub.cn/runninghub-api-doc-cn/)、[V2 查询](https://www.runninghub.cn/runninghub-api-doc-cn/api-425767306) |
| fal | 统一接入成熟图像/视频/音频模型，异步队列 | 提供持久队列、状态、回调、价格查询；运行中取消属于请求，不保证计算已停止。支持禁止自动重试与控制数据保留；不能在取消后直接宣称不计费。[队列](https://fal.ai/docs/documentation/model-apis/inference/queue)、[定价](https://fal.ai/docs/documentation/model-apis/pricing)、[保留和重试设置](https://fal.ai/docs/documentation/model-apis/common-parameters) |
| Replicate | 需要广泛模型或自定义模型托管时的候选 | API 输入、输出、文件与日志默认一小时后删除，持久交付需及时保存副本；暂不增加第二套集成维护成本。[数据保留](https://replicate.com/docs/topics/predictions/data-retention) |

后续多模态模块采用独立任务生命周期：草稿/估价 → 用户确认目标与预算 → 提交并保存供应商任务 id → 查询/回调 → 保存结果 → 可下载。取消请求与供应商最终取消分开表示；超时不盲目重新提交，不在不确定是否扣费时自动换供应商。不将聊天记忆或私人照片默认发给所有平台。

自建流程的链接/ID、导入源 JSON 和输入字段已记录；云端 API 执行仍待联调。RunningHub 的 `nodeInfoList` 通过 `nodeId`、`fieldName` 和 `fieldValue` 覆盖节点参数；节点连线与纯前端参数不能作为通用可编辑字段。图片可先用上传接口取得文件名后交给工作流的 LoadImage。字段映射须由目标工作流决定，不能凭空编造。[官方节点参数说明](https://www.runninghub.cn/runninghub-api-doc-cn/doc-8287336)

比较实验应统一模型/工作流版本、分辨率、时长和输入，覆盖文本生图、参考图编辑、角色连续性、图生视频和语音；记录成功率、首次结果延迟、总延迟、实际费用、重试费用和人工效果选择。用户授权后已在 RunningHub 网页完成两张图像样本，总计 54 RH 币；本地后端已配置 RunningHub 凭据并通过鉴权和旧任务查询，新建生成 API 待验收，也没有跨平台对照数据，不提供虚构的 API 单价或平台胜出结论。
