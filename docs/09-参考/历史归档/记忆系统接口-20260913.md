# 记忆系统接口补充合同 · 2026-09-13

> 当前工作区实现。所有端点需要本人登录；输入内容不得进入日志。此合同取代旧 API 文档中同步重建与草稿自动参与聊天的描述。

## 正式记忆

| 方法与路径 | 请求 / 响应 |
|---|---|
| POST /api/memories | type、content、importance、tags；候选确认另带 origin=suggestion 与 sourceRef（本人用户消息）。201 返回正式记忆 |
| GET /api/memories | q、type、page、limit；limit 默认 20，最多 100。返回 data、total、page、limit |
| GET /api/memories/:id | 当前记忆、revision、origin、sources、importedAt；机器向量剥离 |
| PUT /api/memories/:id | 要修改的字段及 expectedRevision；正文/类型变化触发依赖失效 |
| GET /api/memories/:id/revisions | { revisions: [...] }，修订倒序，含确认动作/时间/来源/导入标记 |
| POST /api/memories/:id/restore | { revision, expectedRevision }，恢复目标旧版，返回新修订 |
| DELETE /api/memories/:id | 永久清除本条、历史、投影、关系及依赖引用/草稿；聊天不受影响 |
| DELETE /api/memories | 清空本人的正式记忆及依赖 |

类型 semantic / episodic / procedural；正文 1–2000 字、重要度 1–10、标签最多 10 项且每项 1–30 字。手动创建不能通过伪造 origin 或 sources 获得机器确认身份；正式来源由服务端确认路径校验。

来源形状：
```json
{ "type": "memory", "id": "owned-memory-id", "revision": 2, "quote": "精确引用片段", "status": "verified" }
```
用户消息来源使用 type=message，含本人用户消息 ID 与精确片段。导入来源可标为 imported 或 missing；missing 不构成访问外部对象的权限。

编辑和恢复示例：
```json
{ "content": "我现在更喜欢游泳", "expectedRevision": 1 }
```
```json
{ "revision": 1, "expectedRevision": 2 }
```
恢复后为第 3 版。修订缺失、过期或状态冲突返回 409；正式记忆接口含 code=MEMORY_CONFLICT。前端保留编辑文本，重新读取并核对最新版本后才可再次保存。无效形状 400，非本人或不存在对象 404。

## 草稿与关系

| 方法与路径 | 行为 |
|---|---|
| GET /api/derived?status= | active / needs_review / promoted / resolved / dismissed / all |
| POST /api/derived/analyze | 固定模拟预览，不读私人上下文，不持久化 |
| POST /api/derived/rebuild | 固定模拟预览，不清除现有内容 |
| POST /api/derived/:id/promote | expectedRevision，可选 type/importance/tags；有可靠来源才直接确认 |
| POST /api/derived/:id/resolve | 冲突条目的 content 与 expectedRevision；同一正式写入事务 |
| POST /api/derived/:id/dismiss | 忽略当前可处理草稿 |
| DELETE /api/derived | 只清除 active / dismissed / needs_review，不删除正式历史 |
| GET /api/derived/edges?status= | derived / canonical / needs_review / dismissed / all；返回两端当前内容与修订、依据版本和 decisions |
| POST /api/derived/edges/:id/promote | expectedRevision、expectedFromRevision、expectedToRevision；确认或重审后重新确认 |
| POST /api/derived/edges/:id/dismiss | 移除关系，保留决定记录 |

无可验证来源或 needs_review 的草稿必须在人工核对后携带 asManual=true 和明确 content，保存为本人的手动确认。dismissed 等已拒绝状态不能用 asManual 跳过。等价的晋升/厘清/关系确认重试返回原对象；版本或处理内容不一致返回 409。

关系正文或类型变化时退出聊天，待重新确认。聊天只加入两端版本仍匹配的 canonical 关系，保留 similar / related / contradicts 类型。冲突不能被自动裁定。

## 索引任务

| 方法与路径 | 行为 |
|---|---|
| POST /api/memories/index-jobs | { mode: "repair" } 或 { mode: "rebuild" }，返回 202 任务对象；已有活跃任务时复用 |
| GET /api/memories/index-jobs/latest | 最新任务或 null |
| GET /api/memories/index-jobs/:id | 本人的任务及进度 |
| POST /api/memories/index-jobs/:id/cancel | 幂等取消；已终止任务原样返回 |
| POST /api/memories/embeddings/rebuild | 兼容入口，转为 rebuild 任务，返回 202，不再返回同步汇总 |

任务对象：
```json
{ "id": "job-id", "mode": "repair", "status": "queued", "total": 4, "processed": 0, "embedded": 0, "skipped": 0, "failed": 0, "errorCode": null }
```

状态 queued / running / completed / cancelled / interrupted / failed。completed 且 failed>0 表示处理结束但有失败项，可重新执行 repair；不能仅依据 202 判定完成。每个用户同时一个任务。

缺向量配置返回 503 EMBEDDING_NOT_CONFIGURED；未授权返回 503 CLOUD_NOT_CONSENTED。单条向量失败记入任务计数，聊天与保存照常使用关键词路径。新结果验证后替换，旧有效结果不因失败被清空。

进度 GET 独立限流 120 次/分钟/用户，其他接口保留既有限流与身份检查。

## 状态展示

GET /api/llm/status 保留原聊天状态，并增加：
```json
{
  "embedding": { "configured": false, "model": null, "mode": "keyword", "available": null },
  "workGeneration": { "mode": "mock", "cloudConnected": false, "persisted": false }
}
```

workGeneration 的完整模拟标记以 workCloudService 的 execution 合同为准。configured 只表示配置齐全；available=null 表示未探测，不能展示成在线成功。工作台生成固定模拟，聊天通道配置和独立向量配置不能互相推断。

## v2 导出与导入

GET /api/user/export：顶层 version=2，保留原业务段并增加 memoryBundle。memoryBundle.version=2；memories 使用稳定包内 id，包含当前快照与 revisions；edges 包含 from/to 包内引用、关系类型、状态、依据修订、结构化 evidence 与 decisions。memoryBundle 只包含正式记忆和 canonical/needs_review 关系，不含机器向量或未确认草稿。原顶层派生记录仍可随完整资料导出，但不参与导入确认。

POST /api/user/import/preview：输入完整 v1/v2 包，返回 format、memoryEpoch、memoryCandidates、edges、角色/人格预览及说明。v2 候选 state 为 new / duplicate / conflict，不落库。缺失外部聊天来源在应用后标记 missing。

POST /api/user/import/apply：
```json
{
  "memoryBundle": { "version": 2, "memories": [], "edges": [] },
  "expectedMemoryEpoch": 7,
  "selectedIds": ["portable-memory-a", "portable-memory-b"],
  "selectedEdgeIds": ["portable-edge-id"]
}
```
以上示例中的空数组仅示意包结构；选择项必须实际存在于所提交的完整包中。可以继续附带经预览确认的 role 和 persona，范围沿用旧版。

- 所有记忆导入（包括 v1 产生的 memories 候选）必须携带预览返回的 expectedMemoryEpoch。资料在预览后变化返回 409，整批不写入。旧预览不能在删除后复活记忆。
- 同一包重新预览并应用，已有相同内容跳过。当前内容或完整历史不同返回 409，不覆盖。
- 选中的关系须同时选择两端记忆；关系依据只能引用这两端的包内版本。引用必须对应真实片段，否则标记缺失。
- 完整连续版本、当前内容、类型、来源等不一致返回 400；非法选择和关系引用返回 400。
- 应用在同一用户事务中完成，包含角色/人格变更。响应包含 memoriesApplied、memoriesSkipped、edgesApplied 等原有结果字段。
- 云端授权不会导入；AI 草稿不会被自动确认。原聊天不导入，因此聊天来源可能缺失。
- 包大小上限 10MB，v2 最多 10000 条记忆、20000 条关系。机器向量不随包迁移，之后可显式 repair。
