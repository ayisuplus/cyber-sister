# 本地推理服务部署完成

> [!IMPORTANT]
> 历史/未来方案归档：本文不代表 2026-10-01 内测实现。当前以仓库根 README、`docs/Spec_赛博姐妹_v1.0.md` 和 `docs/deployment/internal-runbook.md` 为准；微服务、Kubernetes、Redis、向量数据库、模型训练与公开发布均为后置方案。

## 概述

放弃 ModelScope 创空间（配置复杂、Git推送卡住），改用本地推理方案，直接在 RTX 5090 上运行模型，提供 OpenAI 兼容 API。

## 架构

```
前端 (web-app) → 后端 (Node.js:3000) → 推理服务 (Python:8000) → GPU (RTX 5090)
```

## 关键数据

- **模型**: Qwen3-VL-8B bf16，16.3GB 显存占用
- **推理速度**: ~6 tokens/s（5090 bf16 无量化）
- **首次响应**: 1.3s（短回复），3-5s（长回复）
- **API**: OpenAI 兼容 `/v1/chat/completions`

## 文件

### 推理服务 (`LLM/serving/`)
| 文件 | 用途 |
|------|------|
| `server.py` | FastAPI 推理服务，OpenAI 兼容 API |
| `test_api.py` | 单轮测试 |
| `test_multiturn.py` | 多轮对话测试 |
| `test_e2e.py` | 端到端测试（注册→发消息） |

### 后端改动 (`Agent/server/`)
| 文件 | 改动 |
|------|------|
| `src/services/llmService.js` | 重写，加入真实 LLM 调用 + mock fallback |
| `src/routes/chat.js` | 传入历史消息，改为 async 调用 |
| `.env` | 添加 LLM_API_URL 配置 |

### 启动
- 双击 `start.bat` 一键启动推理服务+后端
- 前端：`cd web-app && npm run dev`

## 人设
支持三种人设（toxic/gentle/wild），通过 system prompt 控制，毒舌版效果最佳。

## 后续优化方向
1. 推理速度：可换 vLLM 或 SGLang 提升吞吐量（但Windows支持差，需WSL）
2. 流式响应：前端还没接 SSE，目前是等完整回复后返回
3. 公网访问：需要时加 Cloudflare Tunnel
4. 模型迭代：重新训练后替换 `outputs/cyber-sister-qwen3-8b-bf16/` 目录重启即可
